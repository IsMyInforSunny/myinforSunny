# 캔바 메인 UI 대화상자 연결 감사

범위: `components/workbench.tsx`, `components/review-dialog.tsx`, 연결된 헤더와 공용 검토 컴포넌트를 읽기 전용으로 검토했다. 본 담당자는 이 문서만 수정했다. Claude 담당 `components/canva-dashboard.tsx`, `app/forecast.css`는 수정하지 않았다.

이 기록은 정적 검토다. 전체 타입 검사·테스트·빌드 및 실제 브라우저 조작 검증은 통합 담당자의 결과와 구분한다.

## 보존된 연결

- 메인 `CanvaDashboard`의 입력·좌표 콜백은 해당 `view`를 열고 근거·추천 콜백은 근거 대화상자를 열어 기존 섹션으로 이동한다.
- `showDetails`는 대화상자를 연 뒤 `detailsVisible`을 설정하고 `analysis-details` 또는 `related-review`로 스크롤한다. 관련 DOM ID가 유지되어 있다.
- `selectSpan`은 근거 대화상자를 열고 선택 인용을 `highlight`에 넣어 원문을 강조한다. TopicDistribution·EvidenceButton·Perspectives에서 이 콜백을 사용한다. `ArticleReview` 자체 밑줄 이유 선택은 내부 상태로 유지된다.
- 새 분석 수용 시 이전 연구·대조·선택 인용을 초기화하며 결과 메인으로 포커스를 옮긴다. 요청의 AbortController/sequence 경쟁 방지와 실제 분석 ID별 연구 컴포넌트 key가 유지된다.
- 공개자료·전송 동의, 개인정보 탐지, stale 시 수동대조 차단과 외부조사 비활성 조건은 보존되어 있다.
- 내보내기의 원문/인용 포함 선택은 기본 false이며 미리보기와 다운로드가 근거 대화상자 안에 남아 있다. 다운로드에는 사용자 클릭이 필요하다.
- ReviewDialog는 네이티브 `dialog.showModal()`을 사용하여 배경을 비활성화하고 Esc(onCancel), 닫기 버튼, 배경 클릭을 닫기 상태로 연결한다. 네 대화상자의 자식은 닫혀도 마운트 상태라 입력/대조 폼과 메모리 동작 기록이 전환마다 사라지지 않는다.

## 발견 사항과 수정 권고

### 우선: 닫힌 대화상자로 향하는 건너뛰기 링크

헤더의 `href="#article-editor"`는 닫힌 입력 대화상자 안을 가리킨다. 해시 이동만으로 `showModal()`이나 `setView('input')`이 호출되지 않으므로 키보드 사용자의 입력 진입 경로가 끊긴다. 링크 클릭/해시 변경을 Workbench 입력 열기와 연결하거나 건너뛰기 대상을 메인의 접근 가능한 입력 열기 버튼으로 바꿔야 한다.

### 우선: 근거 대화상자에서 수동대조 오류와 재동의를 확인할 수 없음

`runVerify`는 선택 주장·자료 누락, 전송 동의 누락 및 API 실패를 `setError`로 알린다. 하지만 오류 출력은 전역과 입력 대화상자 안에만 있고 현재 열린 근거 대화상자 안에는 없다. 네이티브 모달이 배경을 비활성화하므로 현재 화면에서 실패 이유를 확인하기 어렵다.

참고자료 편집은 전송 동의를 false로 되돌리지만 전송 동의 체크박스는 입력 대화상자에만 있다. 공개자료 재확인과 대조 자료 전송 동의 UI를 근거 대화상자 안에도 제공하고 해당 오류를 현 대화상자에서 알리는 편이 적절하다. 동의 없이 전송되는 오류는 아니며 현재는 요청 자체가 차단된다.

### 좌표 예시 진입이 좌표 대화상자를 닫음

좌표 빈 상태의 “예시로 좌표 체험 시작하기”는 `loadExample('supported')`를 호출한다. 성공 시 `accept()`가 `setView(null)`을 실행하여 좌표창이 닫힌다. 좌표를 체험한다는 버튼 설명에 맞게 분석 성공 뒤 좌표 대화상자를 다시 열고 가상 좌표 선택의 다음 단계를 알려야 한다.

### 외부 선택 본문 진입

`#selection=` 분기는 본문만 채운다. 입력창이 대화상자로 옮겨진 뒤에는 선택된 본문이 바로 보이지 않는다. 선택 문자열을 정상 수용했을 때 입력 대화상자도 열면 외부 선택 기능의 이전 진입 의도를 보존할 수 있다.

### 브라우저로 확인할 항목

- 입력 분석 성공 시 native close의 자동 포커스 복귀와 `focusReport()`의 RAF가 충돌하지 않는지.
- 입력→근거→좌표 전환에서 한 번에 하나의 대화상자만 top layer에 남는지, Esc/닫기 뒤 호출 버튼으로 돌아오는지.
- 추천 버튼의 목적지가 근거 모달 내부 스크롤에 실제로 나타나는지.
- 원문 인용 버튼을 눌렀을 때 강조 부분과 스크롤 대상이 일치하는지.
- 모바일에서 닫기 버튼과 긴 분석/참고자료 영역에 접근할 수 있는지.
- 요청 취소 알림이 배경에만 남지 않는지. 현재 전역 취소 고지는 입력 모달이 열린 상태에서 보이지 않을 수 있다.

실제 외부 API, 키 읽기, 설치, 배포, 테스트 실행은 이 감사에서 수행하지 않았다. 구현 담당자에게 주요 회귀를 먼저 메시지로 전달했다.

## 통합 담당자의 후속 수정

- 건너뛰기 링크를 닫힌 입력창 대신 포커스 가능한 `main-content`로 연결했다.
- 근거 대화상자 안에 오류와 전송 동의 재확인을 추가했다.
- 좌표 예시 로딩 뒤 좌표 대화상자를 다시 열도록 연결했다.
- 정상적인 `#selection=` 본문 수용 시 입력 대화상자를 연다.
- 입력 대화상자 안에 요청 취소 안내를 표시한다.
- 제어 상태에 따른 programmatic close 이벤트가 새 대화상자를 닫지 않도록 native onClose 상태 중복 변경을 제거했다.

실제 조작 결과는 최종 세션 기록과 브라우저 로그를 확인한다.
