# 실제 기사 기능 점검과 수정 · 2026-11-12

## 판정

현재 공개 버전 40을 **세 점수와 다른 관점 추천이 모두 동작하는 완성본으로 판정할 수 없다.** 실제 기사 URL 분석이 완료되지 않았다. 아래 코드 수정은 로컬 검증 결과이며 공개 사이트 반영 결과와 구분한다.

## 직접 화면 점검 제한

- 요청에 따라 Computer Use의 Windows 앱·창 목록을 조회했다. 연결된 창이 없었다.
- Edge 실행은 `Computer Use app approval timed out`으로 종료됐다.
- 브라우저 연결을 추가 확인했으나 `The browser access host is unavailable`, 브라우저 목록 없음이었다.
- 사용자에게 Computer Use 연결 허용과 브라우저 창 열기를 요청했다. 클릭·화면 검증을 완료했다고 주장하지 않는다.

## 실제 기사와 실서비스 호출

### 공개 사이트의 원래 요청 설정

- 기사: [양치만으로 충치균 죽는 칫솔모 관련 한겨레 과학 기사](https://www.hani.co.kr/arti/science/science_general/1286549.html)
- 공개 사이트 `/api/analyze`에 `kind:url`로 입력. 가상 예시를 사용하지 않았다.
- `/api/capabilities`: NVIDIA, live/search/directFetch/webFetch 모두 활성, 본문 8,000자.
- 요청 ID: `ac3563fc-5c3a-41bc-baa0-f47f958bb478`.
- 서버 본문 취득: 252ms. NVIDIA 응답 헤더·첫 delta: 46,288ms. 최종 JSON 콘텐츠 도착 로그 없음.
- 호출 클라이언트가 300초 HTTP 헤더 제한으로 실패했고, 서버 로그에서도 약 299,998ms 후 canceled로 기록됐다.
- 따라서 이 실제 기사에서 자극·출처 명시·본문 입장과 추천의 최종 표시 성공을 확인하지 못했다.
- NVIDIA 모델 목록 조회는 530ms, HTTP 200, 선택 모델 존재. 모델 목록 접근 성공은 추론 성공을 뜻하지 않는다.

### 로컬 실제 기사 진단

- 3,000건 보존 자료 중 [데일리안 전기요금 기사](https://www.dailian.co.kr/news/view/1703329), 본문 2,326자로 동일 분석 함수 시험.
- 모델 문서의 숫자 reasoning effort를 시험한 진단 요청은 약 207.8초 뒤 HTTP 400에 대응하는 `PROVIDER_REQUEST_INVALID`로 실패했다.
- **이 숫자 옵션은 제품 코드에 적용하지 않았다.** 이 진단 실패를 원래 제품 요청의 설정 오류로 일반화하지 않는다.
- [보성 주택·창고 화재 관련 프레시안 기사](https://www.pressian.com/pages/articles/2024020614182130218), 본문 384자로 `reasoning_effort:low`를 시험한 진단도 약 300.3초 후 응답 헤더를 받지 못하고 `PROVIDER_UNAVAILABLE`로 실패했다. 이 옵션 역시 제품에 적용하지 않았다.
- 같은 384자 기사를 **추론 옵션을 추가하지 않은 제품 원래 설정**으로도 시험했다. 약 284.6초 후 응답 헤더가 왔으나 최종 콘텐츠를 얻지 못하고 공급자 스트림 처리에서 `PROVIDER_UNAVAILABLE`로 실패했다. 입력을 짧게 해도 이번 실행 환경에서는 실시간 분석 완료를 확인하지 못했다.
- 따라서 실제 기사 분석 성공 0건이며, 실제 다른 관점 추천 성공을 확인한 건수도 0건이다. 모델 호출 실패를 점수 0점이나 정상 완료로 바꾸지 않았다.
- 원문·키·모델 출력은 `.sites-runtime/` 안의 무시된 로컬 자료로만 보존한다.

## 발견하고 수정한 제품 결함

1. **분석과 대조의 본문 크기 불일치.** 분석은 8,000자를 받지만 `validateVerifyInput`은 2,000자 초과를 거절했다. 이 함수는 수동 대조와 직접 URL 근거 연결·자동 조사에 공용으로 쓰인다. `MAX_ARTICLE_CHARACTERS`를 계약·URL 분석·기능 상태·대조 검사에서 공유하게 했다.
2. **자동 조사에 남아 있던 24문장 제한.** 분석 이후 `validateResearch`가 24문장 초과를 거절했다. 이 별도 제한을 제거하고 기존 본문 크기·문장 구간·인용·개인정보 검사를 유지했다. 모델 토큰 보호나 검색 한도를 완화하지 않았다.
3. **같은/다른 관점 표시 기준 불일치.** 메인 화면은 입력 본문과의 관계를 사용하지만 상세 화면은 비교 명제의 지지/반대를 그대로 같은/다른 입장으로 표시했다. 입력 본문이 명제에 반대할 때 뜻이 뒤집히는 오류다. 공용 `recommendationLabel`로 통일했다. 본문 방향을 확정하지 못하면 명제 찬성/반대로 표시하고 본문과 반대라고 단정하지 않는다.
4. **입력 기사 자체의 재추천.** 검증된 추천과 수집 메타데이터 후보에서 입력 기사 URL을 제외한다. 검증된 추천은 URL 정규화로 추적 인자·www·fragment 차이도 같은 기사로 취급한다.
5. **관점 추천이 모든 사실 대조 뒤로 밀림.** 조사 실행기가 관점 검색·대조를 먼저 처리하게 했다. 서버 서명 계획의 원래 queryIndex를 보존하고 검색 간격·동의·취소·중복 제외를 유지한다.

## 각 기능의 실제 의미와 남은 일

| 기능 | 구현과 남은 제한 |
| --- | --- |
| 자극·공격 | AI의 문장 판정과 검증된 인용으로 자연 문장 비율을 계산한다. 미판정은 범위/대기다. 현재 실제 전체 호출 성공 미확인. |
| 신뢰 기본 숫자 | 추출한 사실 주장 중 이름 있는 출처가 명시된 비율. 사실 정확도나 진실 확률이 아니다. 현재 실제 전체 호출 성공 미확인. |
| 논점 관점 | 본문 근거가 있는 support/oppose/mixed 등 분류. 막대 위치는 분류 표시이며 강도·확률 점수가 아니다. |
| 수치 편향/SVM | 공개 승인된 모델이 없으므로 계산 대기. 매체 식별 실험을 편향 정확도로 바꾸거나 임의 숫자를 만들지 않았다. |
| 다른 관점 기사 | 같은 비교 명제에 대해 원문 취득·입장 인용 검증된 결과만 분류. 수집 메타데이터 후보는 대조 전이다. 이번에 실제 추천 성공은 확인하지 못했다. |
| 같은 주제 상대 기준 | 이전 1단계의 규칙 기반 두 지표. 실시간 LLM 점수나 편향 모델과 혼합하지 않는다. |

실시간 추론 완료와 실제 비교 기사 취득·입장 대조가 해결돼야 사용자 요청의 전체 완료 기준을 충족한다. 사람 평가·독립 정확도 검증을 수행했다고 주장하지 않는다.

## 검증

- `npm run typecheck`: 통과.
- `npm test`: 875 통과, 선택 실행 13 생략.
- 실제 보존 기사 중 2,000자·24문장을 모두 넘는 본문으로 분석 계약→대조→조사 입력 연속성 통과. 문장 구간 위조는 계속 거절된다. 원문은 테스트 파일에 복사하지 않았다.
- 입력 기사 재추천 제외, 반대 본문의 추천 라벨 반전, 관점 검색 우선 순서 회귀 검사 통과.
- `npm run build`: 최종 수정 뒤 통과. 로컬 미리보기 프로세스가 빌드 폴더를 붙잡아 생긴 EPERM은 이번 작업이 시작한 프로세스만 종료한 뒤 해소됐다.
- 로컬 빌드 서버 `/`, `/api/health`, `/api/capabilities`, `/methodology`: 모두 HTTP 200. 로컬 기본 live/search/fetch는 비활성으로 유지했다. 이는 브라우저 클릭이나 실제 AI 호출 성공 시험이 아니다.
- 개발 미리보기는 Sites 연결 응답의 JSON 파싱 오류로 시작하지 못했다. 빌드된 Worker의 로컬 HTTP 응답 확인으로 대체했으며 화면 검증으로 간주하지 않는다.
- 공개 배포는 상대 기준 계획의 사용자 확인 조건을 유지한다. 공개 버전 40과 로컬 변경을 혼동하지 않는다.
