# 상대 기준 확장 계획 · 같은 쟁점·같은 분기 비교 · 2026-11-14 (Codex 작업용)

사용자 결정(2026-11-14): 편향 상대 기준의 1차 비교 집합을 "같은 사건"에서 **"같은 쟁점·같은 분기"**로 넓힌다. 근거는 [편향 모델 점검](BIAS_MODEL_AUDIT_2026-11-14.md) 2-B-5(같은 사건 묶음이 3,000건 중 1개). 같은 사건 비교는 없어지지 않고, 표본이 있는 사건에서만 위에 얹는 상위 단계가 된다.

이 결정은 AGENTS.md의 2026-11-02 "같은 명제·같은 사건" 기준을 넓힌 것이다. Codex는 루트 `AGENTS.md`에 이 날짜의 결정을 한 줄로 기록한다. **매체당 고유 기사 3건·적격 매체 2곳 기준은 그대로 둔다.** 분기 단위 집합이면 이 기준을 낮추지 않아도 채울 수 있다.

## 정의

- **쟁점**: `lib/data/voice-issues.json`의 6주제×3쟁점(18개). 기사의 주 쟁점은 **기사 단위**로 하나만 정한다(점검 문서 3-1-2). 문장 SVM은 방향·화자만 맡기고, 쟁점 헤드는 "주 쟁점 관련 여부" 이진 판정으로 줄인다.
- **분기**: 발행일(KST) 기준 달력 분기. 발행일이 없는 직접 입력 글은 분기 집합을 쓰지 않고 "전체 기간" 집합만 쓴다.
- **집합(코호트)**: 같은 쟁점 × 같은 분기의 코퍼스 기사 중 좌표가 산출된 기사. 매체 동일가중(각 매체 합이 1/매체 수).
- **적격**: 집합 안에서 고유 기사 ≥3건인 매체가 ≥2곳. 미달이면 반기 → 전체 기간 순으로 넓히고, 화면에 어느 범위와 비교했는지 적는다. 그래도 미달이면 "비교 기사 부족".
- **기준선**: 적격 매체 기사 좌표의 동일가중 중앙값(`compareVoiceCoordinates`의 기존 계산과 같음).
- **점수**: `|입력 좌표 − 기준선| / 2 × 100`, 방향은 부호. 입력 좌표가 **범위**(점검 문서 3-1-3)이면 점수도 범위로 표시하고, 방향은 범위 전체가 기준선 한쪽에 놓일 때만 말한다. 범위가 기준선을 걸치면 "방향 유보".
- **백분위**: 같은 집합에서 입력 좌표의 위치(상위 ○%). 점수와 함께 표시한다.

## 하지 않는 것

- 미확정 문장을 중립으로 바꾸지 않는다. 좌표 범위를 중앙값 점으로 치환하지 않는다.
- 매체별 평균·순위·"이 매체 평소보다"를 만들지 않는다. 매체 이름은 가중과 "비교 매체 4곳" 표기에만 쓴다.
- 좌표 분포 파일에 본문·인용·URL을 넣지 않는다. 추천용 제목·링크는 기존 `article-search-index.json`과 같은 서버 전용 경로를 쓰고, 이용 승인 플래그 검사를 그대로 둔다.
- 정치 좌우 라벨, 사람 정확도, 매체 성향 수치를 만들지 않는다.

## 선행 조건 (점검 문서 3-1의 1~3)

1. 좌표를 취재원 인용 균형과 기자 서술 방향으로 분리 표시한다. 상대 비교의 입력 좌표는 **취재원 인용 균형**을 기본으로 하고, 기자 서술 방향은 보조로 표시한다(기자 방향 문장이 거의 없어 집합을 이루지 못한다).
2. 쟁점을 기사 단위로 고정한다.
3. 적격 조건을 `unresolved===0`에서 `voiceEvidenceBounds` 범위 폭 ≤0.5로 바꾼다.

이 셋이 없으면 코퍼스 기사도 좌표가 0건이라 집합이 생기지 않는다(고정 평가 7건 중 0건).

## 작업 순서

1. **선행 조건 1~3 구현**과 회귀 테스트. 고정 평가 7건에서 좌표(점 또는 범위)가 나오는 기사 수를 다시 기록한다.
2. **오프라인 집합 계산** `research/build_issue_quarter_baselines.*`:
   - 3,000건에 대해 주 쟁점(기사 단위) → 문장 좌표 → 기사 좌표(점/범위)를 계산한다. 모델은 현재 임베딩 후보를 쓰되 결과 파일에 `modelVersion`·`decisionPolicy`·`researchOnly` 표기를 남긴다. 임베딩 호출은 약 7만 문장 1회성이므로 예산 장부에 예약량을 먼저 적고, 하루 한도 안에서 나눠 실행한다.
   - 산출 `lib/data/issue-quarter-baselines.json`: 쟁점×분기(+반기·전체)별 n, 매체별 건수, 동일가중 중앙값, 백분위 경계(5%p), 범위 기사 수(분포 계산에서는 제외하고 건수만), 생성일, 모델 버전. 본문·URL 없음.
   - 산출(서버 전용) 추천 색인: 기사 ID·제목·매체·발행일·URL·좌표. 이용 승인 플래그가 없으면 서버가 응답에서 제외한다(기존 규칙 유지).
   - 집계 보고서를 `docs/test-runs/`에 남긴다: 쟁점×분기별 적격 집합 수, 좌표 있는 기사 비율, 범위 기사 비율.
3. **런타임 연결** `lib/voice-comparison.ts` 또는 새 모듈:
   - 입력 기사 → 주 쟁점 → 좌표 → 집합 선택(분기 → 반기 → 전체) → 기준선 거리 점수·백분위·방향.
   - 같은 사건 매칭(`compareEventBaseline`/`matchLiveVoiceEvent`)이 적격이면 그 결과를 우선 표시하고, 쟁점·분기 결과를 아래에 둔다. 둘 다 있으면 둘 다 보여 준다.
   - 집합의 `modelVersion`·`decisionPolicy`가 입력 좌표와 다르면 비교하지 않는다(기존 규칙).
4. **반대편·같은 편 추천**: 같은 집합에서 기준선 반대편, 입력 좌표의 거울 위치에 가장 가까운 기사 3건과 같은 편 3건. 표시는 제목·매체·날짜·링크만. 입력 기사·학습 원본·같은 본문 해시는 제외(기존 규칙).
5. **화면 문구**: "같은 쟁점(원전 확대)을 다룬 4개 매체 기사 n건(2026년 3분기)과 비교 · 기준선(중앙값) 거리 ○○점 · 상위 ○%". 범위일 때 "○○~○○점 · 방향 유보". 집합 범위를 넓혔으면 "분기 표본 부족으로 전체 기간과 비교"를 적는다.
6. **분석 기준 페이지**: 비교 집합의 정의(쟁점·분기·4매체·2024-01~2026-11), 기준선이 4매체 중앙값이라는 점, 같은 사건 비교와의 관계를 적는다.
7. **검증**: `typecheck`·`test`·`build`. 실제 기사 10건 + 점검 문서의 가상 8건을 같은 입력으로 돌려 "점수가 나온 건수·범위 건수·부족 건수·소요 시간"을 기록한다. AI 라벨 기준이며 정확도로 쓰지 않는다.
8. **배포**는 사용자 확인 뒤에 한다.

## 여전히 결정 대기인 것

- 이용 검토 범위(요약 통계 공개 + 제목·링크 추천). 이 결정 전에는 2번의 추천 색인과 모델 아티팩트를 공개 배포에 넣지 않고, 로컬 빌드에서만 확인한다.
- 같은 사건 조건 변경(사건당 매체 ≥2·총 ≥4건)과 사건 단위 수집.
- 팀원 2명의 60문장 라벨.
