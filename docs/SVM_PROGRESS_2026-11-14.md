## 연결한 기능

1. 문장을 의미 벡터로 바꾼 뒤 방향 유무 → 찬반 방향, 발화자, 쟁점을 각각 선형 SVM으로 분류한다. 낮은 마진은 유보한다. 광고·해시태그·저작권 표시 문장은 집계에서 제외한다.
2. URL 본문 분석과 검색·직접 취득한 관련 기사에 같은 서버 모델 경로를 연결했다. 유효한 운영 모델만 불러오며 실패하면 편향 분석 미완료로 표시한다.
3. 원문 URL·발행일·본문 해시를 서버 서명 토큰으로 묶는다. 비교 기사와 사건 유사성 및 3일 기간을 확인하고, 학습 원본과 중복을 제외한다.
4. 같은 사건·쟁점에서 매체별 고유 기사 3건 이상, 매체 2곳 이상이라는 기존 기준을 유지한다. 표본이 부족하면 상대 점수와 반대쪽 추천은 대기로 남는다.
5. 의미 벡터 캐시와 요청 병합, 실제 사용량 기록, 429 중단, 취소 전파를 구현했다. 자료 취득도 모델을 쓰면 계획·취득·비교에 최소 20.1초 간격을 적용해 기존 분당 3회 요청 제한을 유지한다. 시간당 20회 제한도 유지한다. 따라서 전체 조사가 항상 30초 안에 끝난다고 보장하지 않는다.

## 실제 URL 서버 검사 및 취득 수정

실제 기사 [한수원, 원전 건설 과정서 국민 목소리 청취](https://www.dailian.co.kr/news/view/1667349/)를 빌드된 로컬 서버 `/api/analyze`에 입력했다. 화면 조작 도구가 없어 서버 요청으로 실행했으며 UI 검사로 계산하지 않는다.

- 수정 전: 1.47초 후 HTTP 422 `ARTICLE_BODY_UNAVAILABLE`. 기사 주소가 같은 출처의 제목 포함 주소로 301 이동했으나 취득 코드가 모든 이동을 거부했다.
- 수정: 원래 HTTPS origin 안에서 정확한 허용 목록을 만족하는 이동만 최대 두 번 수동 처리한다. 교차 출처, HTTP, 사용자정보 포함 주소, 반복 이동은 차단한다. 최종 URL을 원문으로 기록한다. 공통 5초 취득 제한과 각 응답의 noai/nosnippet 중단을 유지한다.
- 수정 후: 캐시 miss, HTTP 200 `success`, 전체 15.47초. 원문 839자 전체, 주장 5개, 표현 분석 18개가 반환됐다. AI 응답 완료는 약 12.53초였다.
- 화면과 같은 점수 계산 함수 결과: 자극 표현 0/18 = 0점, 근거 출처 명시 1/5 = 20점. 편향은 운영 SVM 비활성으로 대기, 출처 가중 근거 점수는 외부 자료 대조 전이라 대기다. 출처 명시 점수를 신뢰 점수로 대신 표시하지 않는다.

의미 벡터 제공자 요청도 workerd에서 지원하지 않는 `redirect:error`를 `manual`로 바꾸고 모든 이동 응답을 명시적으로 거부했다. 잘못된 벡터 행은 구조화된 오류로 처리한다. 이것은 공급자 경계 테스트로 검증했으며 활성 SVM의 실제 API 실행 증거는 아니다.

관련 테스트 추가 후 전체 986개 통과(13개 건너뜀), 타입 검사·빌드 통과. 실제 API 호출·응답 상세는 로컬 runtime에만 보존한다. Browser 미연결, 데이터 이용 검토, 비교 표본 확보는 여전히 미완료다.

## 기사 단위 산출 가능성 검사

`scripts/check-voice-article-coverage.mjs`는 고정 평가 기사 7건의 실제 모든 문장을 서비스와 같은 정규화·유보·집계 함수로 검사한다. 문장별 macro-F1만으로 기사 점수 기능의 완성을 판단하지 않기 위한 검사다. 후보 가중치·마진·평가 분할은 바꾸지 않았다.

기존 벡터는 교사 라벨이 명확한 문장 위주였으므로 기사 전체 검사에 고유 문장 7개의 벡터를 보충했다. 기존 예산 장부에서 API 1회·예약 6,500토큰·공급자 보고 155토큰을 사용했다. 장부의 누적 예약은 97,500토큰이다. 원래 입력·벡터·평가 보고서를 덮어쓰지 않고 별도 보충 파일에 저장했다. 새 교사 라벨이나 학습 표본은 생성하지 않았다.

결과는 전체 비광고 문장의 벡터가 있는 기사 6건, 미확정 없는 기사 0건, 기존 기준으로 대표 좌표를 표시할 수 있는 기사 0건이다. 문장 하나는 학습 파티션에도 동일한 정규화 텍스트가 있어 엄격한 평가 분리 조건상 벡터를 재사용하지 않았다. 빈 입력이 아니다. 모든 기사에 실제 분류 유보가 있으므로 입력 누락만 채워도 기사 좌표는 나오지 않았다. 일부 기사에서 11~12개의 방향 문장을 분류했지만 기사 전체의 미확정 6~7개 때문에 대표 좌표를 제공할 수 없었다.

따라서 후보의 문장 성능 기준 통과와 기사 점수 산출 준비를 구분하도록 상태 데이터와 화면 안내를 수정했다. 후보를 단순히 ‘적용 대기’라고 설명하지 않는다. 현재 조건을 유지한 채 완성하려면 문맥·혼합 발화·쟁점 판별의 기사 단위 성능을 개선하고 독립 기사 단위 평가에서 실제 산출 가능성을 입증해야 한다. 완성을 위해 기존 고정 평가에 맞춰 마진을 낮추거나, 미확정 문장을 중립으로 바꾸거나, 비교 표본 없이 임의 점수를 만들지 않는다.

## 미확정 문장의 영향 범위 계산

`voiceEvidenceBounds`를 기사 집계와 상세 화면에 연결했다. 확정 찬성 S개·반대 O개와 해당 쟁점에 영향을 줄 수 있는 미확정 U개에 대해 관측 좌표는 기존 `(S−O)/(S+O)`이고, 가능한 범위는 `[(S−O−U)/(S+O+U), (S−O+U)/(S+O+U)]`다. 쟁점 불명 문장은 모든 쟁점의 U에 포함한다. 확정된 중립은 분모에 더하지 않는다. 방향 문장 3개 미만이면 관측 좌표는 여전히 산출 보류한다. 이 범위는 모든 미확정 문장이 찬성·반대·중립으로 분류될 때의 산술 범위이며, 이미 분류한 문장의 오분류 위험까지 포함한 통계적 신뢰구간이 아니다.

고정 평가 실제 기사 7건을 보관 벡터로 재계산했다(API 추가 호출 없음). 2건에 관측 좌표가 있었다. 한 기사는 찬성 11·반대 0·관련 미확정 6으로 관측 +1.00, 범위 +0.2941~+1.00이다. 다른 기사는 찬성 2·반대 10·관련 미확정 4로 관측 −0.6667, 범위 −0.75~−0.25다. 나머지는 충분한 방향 문장이 없다. 해당 부분값을 최종 상대 편향점수나 추천 적격 좌표로 승격하지 않는다. `mainVoiceIssue` 및 비교 집합의 확정 조건은 유지한다.

원인 분리 검토에서 중립 방향이 확실해도 발화자 또는 쟁점 헤드가 유보되면 전체 문장 방향까지 `uncertain`으로 바뀌는 구조를 확인했다. 향후 방향·쟁점·발화자 불확실성을 분리하는 새 모델 계약을 학습 데이터와 사건 그룹 교차검증으로 개발해야 한다. 기존 고정 평가를 이용해 임계값을 선택하지 않으며 새 계약은 독립 평가·release 검증을 함께 갱신해야 한다. 현재 모델은 원전 쟁점 연구 후보이며 일반 기사 전체를 지원하는 운영 모델이 아니다.

검증: 타입 검사 통과, 전체 테스트 989개 통과·13개 건너뜀, 빌드 통과. 범위 계산 검사는 가능한 찬성/반대/중립 배정을 열거해 모든 결과가 범위 안에 있는지 확인했다. 빌드된 로컬 홈페이지 및 `/api/capabilities` HTTP 200을 확인했다. Browser 연결 목록은 비어 있어 화면 조작 검사는 미완료다. 로컬 서버 주소는 `http://127.0.0.1:5184`다.
