# 공개 기사 URL 근거 대조

## 변경

- `/api/research`에 `operation: "import"`를 추가했다. 현재 분석의 사실 주장 또는 비교 대상과 공개 HTTPS 기사 주소를 최대 2개 받는다.
- 직접 취득은 검색 서비스 인증과 분리했다. 분석 준비, DB, `ENABLE_DIRECT_FETCH=true`, `NEWS_TERMS_APPROVED=true`, 정확한 `ALLOWED_RETRIEVAL_HOSTS`가 필요하다. 직접 HTTP 취득은 기본 GDELT 어댑터 환경에서만 허용하며 Firecrawl 계정 준비 조건을 우회하지 않는다.
- `capabilities.directFetch`가 실제 직접 취득 조건을 표시한다. `webFetch`만 보고 직접 취득 폼을 활성화하지 않는다.
- 서버가 취득한 본문·해시·발행일·취득시각·발췌 위치를 기존 사용자 바인딩 서명 근거로 전달한다. 브라우저의 임의 `web_fetched` 필드는 신뢰하지 않는다.
- 검색과 직접 취득은 기존 DB 요청 한도를 공유한다. 같은 분석·주장·정규화 URL·사용자의 재전송은 차단한다. 대조 모델 호출은 기존 예약·분당·일일·동시 처리 한도를 유지한다.
- 화면은 주소 수정 시 전송 동의를 해제하며 취소·입력 변경 뒤 늦은 응답을 반영하지 않는다. 직전 직접 대조와 분석 시각을 고려해 분당 호출 간격을 둔다. 다른 창이나 수동 대조와의 충돌은 서버 예산 제한이 처리하며 자동 재시도하지 않는다.
- 직접 취득 결과도 공통 신뢰성 검토·추천·내보내기로 전달한다. 자동 검색했다고 표시하지 않는다. 선택 주장에는 최신 대조의 자료가 반영되며 모든 과거 자료를 누적 합산하지 않는다.

## 본문 추출 수정

- ASP.NET 문서 전체를 감싼 정확한 `aspnetForm` 안의 명시적 기사 본문은 보존한다. 중첩 댓글 양식은 제외한다.
- `articleBody`, `article_body`, `news_view` 본문 영역을 추천 기사 카드보다 우선한다.
- 스크립트만 있는 페이지의 `<!DOCTYPE html>`을 본문으로 취급하지 않는다. 조선일보의 클라이언트 데이터 본문 추출은 구현하지 않았으며 스크립트를 실행하지 않는다.
- 로컬에 저장된 실제 HTML 검사: 오마이뉴스 2,035자, 동아일보 1,255자 본문 확인. 조선일보는 빈 본문으로 처리한다. 이 검사는 네트워크 접근 성공이나 학습 이용 승인을 뜻하지 않는다.

## 검증과 운영 한계

- 웹사이트 전용 자동 검사 651개 통과, 실제 API 선택 검사 13개 제외. 타입 검사 및 제품 빌드 통과.
- 브라우저의 모의 API로 직접 취득 → 대조 → 공통 검토·내보내기, 주소 변경 후 재동의, 취소 이후 늦은 응답 무시, 375px 화면을 검사했다. 기존 자동 조사 취소·재시작·입력 변경 흐름도 통과했다.
- 이번 작업의 실제 외부 모델·검색 호출은 0회다. 직접 URL 기능의 실제 운영 기사·모델 종단 검증은 아직 수행하지 않았다.
- 공개 사이트의 직접 취득 활성화, 검색 활성화 및 출처 이용 조건 확인을 완료했다고 주장하지 않는다. 새 설정은 기본 비활성이다.
- 편향 모델은 계속 `null`이다. 수집된 로컬 본문 후보 8건/5매체는 학습 승인 0건이며, 독립 원본 수 미확정·발행일 누락·기사 형식 혼재를 검토해야 한다. 실제 사람 평가나 모델 성능은 생성하지 않았다.

검증 기록: `docs/test-runs/2026-11-04-resume-direct/`. 로컬 기사 본문과 HTML은 Git에 포함하지 않는다.
