## 지난 회차 검토에서 나온 문제

1. **비교가 성립해도 변별이 안 된다.** 의대·원전 실제 링크 모두 점수 0–25점, 방향 유보, 반대편 후보 0건이었다. 원전 전체 기간 기준선이 `[0.5, 1.0]`처럼 폭 0.5인 구간이고 입력도 폭 ≤0.5 구간이라, 구조상 거의 항상 겹친다. 지금 설계로는 대부분의 기사가 같은 결과를 받는다.
2. **좌표가 양 끝에 몰릴 가능성.** 방향 문장 3~4개가 한쪽이면 좌표가 ±1이다(원전 수명연장 기준선 중앙값 −1). 분포를 확인한 적이 없다.
3. **좌표를 만든 모델이 아직 검증되지 않았다.** 작업 8(정제 라벨 재채점, 합의 평가 세트, 쟁점 예시)이 시작되지 않았다. 지금 점수는 오류가 확인된 원시 라벨로 학습한 후보에서 나온다.
4. **버그 4건.**
   - 최저임금 링크: LLM 출력 길이 제한으로 502.
   - 주택 링크: 모델이 없을 때 저장된 캐시를 재사용해 좌표 누락.
   - 보관 기사와 같은 입력: `input_in_population`으로 비교 거부(자기 제외 후 재집계가 아님).
   - `nvidia-budget.test.ts`: 전체 병렬 실행에서 시간 초과.
5. **주택 공급:** 적격 좌표가 7건뿐이다. 어느 단계에서 탈락하는지 모른다.
6. 최저임금 기준선의 건수·매체 수가 기록에 없다("확인된 묶음 1개").

- G1. **판별률**을 측정하고 올린다. 판별률 = 적격 보관 기사 각각을 입력으로 넣고 나머지와 비교했을 때(자기 제외) 방향이 정해지는 기사 비율. 쟁점별로 기록한다. API 호출 없이 계산한다.
- G2. 작업 8의 필수 3단계를 끝내고, 정제 라벨로 재학습한 후보가 기존 게이트를 통과하는지 기록한다.
- G3. 의대·원전·최저임금에서 실제 링크 각 2건이 오류 없이 끝나고, 방향이 정해진 경우 반대편 후보가, 유보인 경우 아래 작업 4의 보조 표시가 나온다.
- G4. 버그 4건 수정, 전체 검증 1회 통과.

## 작업 1 · 진단 먼저 (API 0회, 1시간 이내)

`docs/test-runs/bias-diagnosis-2026-11-16.json` 하나에 쟁점별로 기록한다.

- **탈락 단계표:** 주제 기사 수 → 쟁점 배정 → 임베딩 완료 → 방향 문장 ≥3 → 구간 폭 ≤0.5 → 매체별 적격 건수. 4개 쟁점 모두.
- **좌표 분포:** 적격 기사의 하한·상한·관측 좌표를 0.25 간격 9칸 히스토그램으로. ±1에 몰린 비율.
- **미확정 원인:** 적격·부적격 기사의 미확정 문장을 방향 유보 / 화자 유보 / 쟁점 무관으로 나눈 건수.
- **기준선:** 쟁점별 `[B_low, B_high]`, 건수, 매체 수(최저임금 포함).
- **판별률(G1 기준값):** 자기 제외 비교에서 방향 결정 / 유보 / 기준선 불확실 건수.

이 결과를 보고 작업 3·4의 세부를 정한다. 주택 공급은 탈락 단계표로 원인 한 줄을 적고, 원인이 "방향 문장 부족"이면 이번 회차 시연 대상에서 뺀다.

## 작업 2 · 버그 수정

1. **LLM 출력 길이:** 문장 수가 많은 기사에서 실패한다. 문장별 출력은 ID+기호만 유지하고, 본문 문장이 40개를 넘으면 문장 표시 부분을 40문장씩 나눠 호출한 뒤 합친다(주장·명제는 첫 호출에서만). 실패한 최저임금 링크로 재현 테스트를 만든다.
2. **캐시:** 캐시 키에 편향 모델 식별자(연구 주입 포함)와 사전 계산 스냅샷 해시를 넣는다. 모델이 없던 때의 결과가 모델이 있는 빌드에서 재사용되지 않게 한다.
3. **자기 포함:** 입력이 비교 집합 안에 있으면 그 기사(같은 본문 해시)를 빼고 기준선을 다시 계산해 결과를 낸다. 응답에 `selfExcluded:true`를 넣는다. 매체 적격 조건은 제외 후 다시 검사한다.
4. **테스트 시간 초과:** `nvidia-budget.test.ts`의 해당 검사에 개별 타임아웃을 주거나 그 파일만 순차 실행한다. 다른 테스트의 제한은 바꾸지 않는다.

## 작업 3 · 모델 검증과 재학습 (작업 8 이어서)

1. **(a) 재채점:** 기존 고정 평가 문장에서 원시 라벨과 정제 라벨의 불일치율을 쟁점별로 기록하고, 현재 후보를 정제 라벨로 다시 채점한다(정제 전/후 나란히).
2. **(b) 합의 평가 세트:** 의대·원전·최저임금에서 기사 30건. Lightning과 Groq `openai/gpt-oss-120b`가 각각 라벨, 일치 문장만 정답. Groq는 기록 한도(RPM 30·TPD 200,000) 안에서 30건만. 학습·임계값 선택에 쓰지 않는다.
3. **(c) 쟁점 예시 고정:** 3개 쟁점마다 찬성으로 세는 것 5개, 세지 않는 것 5개.
4. **(d) 재학습:** 정제 라벨(2,834문장 + 검토를 마친 추가분)로 3개 쟁점의 방향·화자 SVM을 다시 학습한다. 남은 18건 검토가 한도로 막히면 그 18건 없이 진행한다.
5. **(e) 좌표 재계산:** 새 후보로 보관 기사 좌표와 기준선을 다시 만들고 작업 1의 진단을 같은 형식으로 다시 돌린다(`…-after.json`). 판별률 전/후를 비교한다.
6. 게이트 미달이면 운영 후보로 표시하지 않고 미달 항목만 기록한다. 이 경우에도 작업 4·5는 "연구 후보" 표기로 진행한다.

LLM–SVM 이중 확인은 이번 회차에서 하지 않는다(미확정을 늘려 구간을 넓히므로 판별률이 먼저다).

## 작업 4 · 방향이 유보될 때의 보조 표시

기존 점수 범위와 방향 규칙은 그대로 둔다. 그 아래에 다음을 추가한다.

1. **인용 구성 3분류:** 각 기사를 구간 기준으로 찬성 쪽 우세(하한 > 0.2), 반대 쪽 우세(상한 < −0.2), 혼합·불확실(그 외)로 나눈다. 비교 집합의 분류별 건수와 입력 기사의 분류를 보여 준다. 예: "같은 쟁점 104건 중 찬성 쪽 인용 우세 61건 · 반대 쪽 22건 · 혼합 21건. 이 기사는 혼합".
2. **분포 막대:** 작업 1의 9칸 히스토그램 위에 입력 기사 구간을 겹쳐 그린다.
3. **구성이 다른 기사:** 방향이 정해지면 기존 "반대편 기사". 유보이면 입력과 **다른 분류**에 속한 기사 중 최신 3건을 "인용 구성이 다른 기사"라는 이름으로 보여 준다. "반대편"이라고 부르지 않는다. 입력이 혼합이면 찬성 우세 1~2건, 반대 우세 1~2건.
4. 임계값 0.2는 설명용 분류 기준이며 점수·게이트에 쓰지 않는다. 화면에 "찬반 문장 수 기준 분류"라고 적는다.
5. 근거 문장: 입력 기사의 찬성·반대 문장을 화자(기자/취재원)와 함께 목록으로 보여 준다(이미 계산된 값).
