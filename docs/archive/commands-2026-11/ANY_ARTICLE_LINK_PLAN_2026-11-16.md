# 임의 기사 링크 분석 계획 · 2026-11-16 (Codex 작업용)

계기: 사용자가 조선일보 기사 링크(`https://www.chosun.com/politics/politics_general/2026/11/16/…`)를 넣었더니 "기사 본문을 가져오지 못했습니다"(`ARTICLE_BODY_UNAVAILABLE`)가 나왔다. 목표는 검색으로 찾은 일반 기사 링크 대부분이 분석되게 하는 것이다. 편향 모델 작업(`CODEX_COMMAND_2026-11-16B.md`)과 별개 작업이며, 그 작업 뒤 또는 병행으로 진행한다.

## 원인 (코드·기록 기준, 오늘 해당 URL을 다시 가져와 보지는 않음)

1. **호스트는 허용돼 있다.** 오류가 `ARTICLE_URL_NOT_ALLOWED`가 아니고, `scripts/start-local-nvidia.mjs`의 허용 목록에 `www.chosun.com`이 있다.
2. **본문이 HTML에 없다.** 조선일보 기사 본문은 페이지의 스크립트 데이터 안에 있고 화면에서 조립된다. 서버는 스크립트를 실행하지 않으므로 추출 결과가 빈 문자열이다(`docs/DIRECT_EVIDENCE_2026-11-04.md:17-18` "조선일보는 빈 본문으로 처리"). `lib/server/retrieval.ts`는 `extracted.text`가 없으면 `null`을 돌려주고, `analyze-url.ts`가 이를 본문 없음으로 처리한다.
3. **정책 문제도 있다.** 11-04 기록상 조선·중앙·한겨레·경향은 robots.txt에 AI·머신러닝 수집 제한이 있다. 서버가 대신 가져오는 방식은 이 매체들에 쓰지 않는 것이 맞다.
4. 구조적 한계: 지금 방식은 **운영자가 등록한 12개 호스트**에서 **서버가 직접 가져온 정적 HTML**만 분석한다. 그 밖의 매체, 포털(네이버·다음) 링크, 스크립트 렌더링 페이지, 로그인·유료 기사는 모두 실패한다.

## 해결 방향: 세 갈래를 함께 쓴다

### A. 사용자의 브라우저가 본문을 넘겨주는 경로 (가장 넓게 해결)
사용자가 이미 보고 있는 화면의 글을 사용자의 브라우저에서 읽어 분석으로 보낸다. 서버가 매체에 접속하지 않으므로 스크립트 렌더링·포털·AI 수집 제한 매체에서도 동작하고, 활동계획서의 "읽던 화면 그대로" 설계와 맞는다.

1. **북마클릿 "이 기사 분석":** 사이트에 끌어다 놓는 버튼을 제공한다. 누르면 현재 페이지에서 제목과 본문(선택 영역 우선, 없으면 `article`·`[itemprop=articleBody]`·가장 긴 문단 묶음)을 추출해 분석 화면을 새 탭으로 열고 `postMessage`로 전달한다. URL 쿼리에 본문을 넣지 않는다.
2. **브라우저 확장(이미 있는 0.2.1):** 같은 추출 코드를 쓰고 "이 페이지 분석" 버튼을 넣는다. 스토어 배포 없이 개발자 모드로 시연한다.
3. 분석 요청은 기존 `kind:'text'` 경로를 쓰되 `sourceUrl`·`sourceTitle`을 함께 보내 화면에 원문 주소를 표시한다. 캐시는 본문 해시 기준. 이 경로의 결과에는 "사용자 브라우저에서 전달된 본문"이라고 표기한다.
4. 개인정보 검사(전화번호·이메일)와 8,000자 제한은 그대로 적용한다.

### B. 서버 추출 개선 (AI 수집을 제한하지 않는 매체에 한해)
1. `lib/server/article-extraction.ts`에 정적 데이터 추출을 추가한다. 스크립트를 실행하지 않고 텍스트로만 파싱한다.
   - JSON-LD `articleBody`(이미 있음)를 `@graph`·배열·`NewsArticle` 하위 타입까지 확장
   - `<script id="__NEXT_DATA__">`의 JSON에서 본문 필드 탐색
   - `<link rel="amphtml">`이 같은 출처·허용 호스트면 AMP 페이지 한 번 더 시도(이동 2회 제한 안에서)
   - 위가 모두 없을 때 문단 밀도 기반 일반 추출(가장 긴 `<p>` 묶음, 메뉴·추천·저작권 문구 제거)
2. 추출 실패 원인을 구분해 돌려준다: `HOST_NOT_SUPPORTED`, `ROBOTS_AI_RESTRICTED`, `SCRIPT_RENDERED`, `ACCESS_RESTRICTED`(로그인·유료·403), `TOO_SHORT`.
3. 매체별 실제 링크 1건씩으로 추출 길이를 기록하는 점검 스크립트를 만든다(`docs/test-runs/extraction-coverage.json`).

### C. 허용 매체 넓히기 (사용자 결정 필요)
지금은 "임의 URL은 네트워크 목적지가 되지 않는다"가 보안 규칙이다. 넓히는 방법은 둘 중 하나다.

- **C1 (권장): 허용 목록을 확대.** robots.txt가 일반·AI 접근을 막지 않는 국내 매체 30~50곳을 등록한다(11-05 조사에서 허용 확인: SBS, 연합뉴스TV, 채널A, 동아, 한국경제, 세계일보, 서울신문, 민중의소리, 시사IN, 뉴시스, 뉴스1 등). 등록 전에 매체별 robots.txt와 추출 결과를 확인해 기록한다.
- **C2: 공개 가져오기.** HTTPS·공인 도메인만, 사설 IP·localhost·포트 차단, DNS 재바인딩 방지, 2MB·5초 제한, 요청마다 robots.txt 확인(호스트별 1시간 캐시), 거부 목록 유지. 보안 위험과 구현량이 더 크다.

포털 링크(네이버·다음 뉴스)는 포털 robots 정책을 먼저 확인한다. 막혀 있으면 서버가 가져오지 않고 A 경로로 안내한다.

### 실패했을 때의 화면
- 오류 문구를 원인별로 바꾼다. 예: "이 매체는 화면에서 본문을 조립해 링크만으로는 가져올 수 없습니다. ‘이 기사 분석’ 버튼을 쓰거나 본문을 붙여 넣어 주세요."
- 실패 즉시 "본문 직접 입력" 탭으로 전환하고 입력란에 커서를 둔다. 북마클릿 안내를 같은 자리에 보여 준다.
- 입력창 아래에 "링크로 바로 분석되는 매체" 목록을 펼쳐 볼 수 있게 한다.

## 작업 순서

1. 실패 원인 코드 분리와 화면 안내(B-2, 실패 화면). 반나절.
2. 북마클릿과 `postMessage` 수신(A-1, A-3). 조선·네이버 뉴스·임의 블로그 기사 3종으로 확인.
3. 서버 추출 개선(B-1)과 점검 스크립트(B-3).
4. 사용자 결정 후 C1 매체 등록.
5. 확장 프로그램에 같은 추출 코드 연결(A-2).

## 지킬 것

- AI 수집을 제한한 매체(조선·중앙·한겨레·경향 등)는 서버가 가져오지 않는다. 헤더를 바꾸거나 다른 경로로 우회하지 않는다. A 경로는 사용자가 자기 브라우저에서 보고 있는 글을 본인이 보내는 것이므로 별개다.
- A 경로로 받은 본문은 저장하지 않고(기존 캐시 규칙), 비교 집합·학습 자료에 넣지 않는다.
- 스크립트를 서버에서 실행하지 않는다. 로그인·유료 기사를 우회하지 않는다.

## 사용자 결정 필요

1. 북마클릿·확장으로 사용자가 보는 화면의 본문을 받아 분석하는 방식(A)을 도입할지.
2. 허용 매체를 C1(목록 확대)로 넓힐지, C2(공개 가져오기)까지 갈지.
