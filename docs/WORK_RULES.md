# 작업 방식 규칙 (Codex·보조 에이전트 공통) · 2026-11-16

목적: 한 곳이 막혔다고 전체가 멈추는 일, 같은 확인을 반복하는 일, 순서대로만 하느라 기다리는 일을 없앤다. 이 규칙은 `AGENTS.md`의 제품·보안 규칙을 바꾸지 않는다. 루트 `AGENTS.md`에 이 파일을 가리키는 한 줄을 추가한다.

## 1. 막혔을 때 (가장 중요)

1. **막힌 항목만 멈춘다.** 그 항목과 무관한 나머지 작업은 같은 회차에 모두 끝낸다. "A가 안 돼서 전체 테스트·빌드·커밋을 보류"하지 않는다.
2. 막힌 지점은 상태 파일에 **세 줄**로 적는다: 무엇이 막혔나 / 확인한 사실 / 선택지 2개와 권장안.
3. 스스로 풀 수 있는지 **20분** 안에 판단한다. 판단 기준:
   - 사실 확인으로 풀리는 문제(플랫폼이 실제로 막는지, 파일이 있는지, 키 설정 이름)는 **직접 확인한다.** 추측으로 멈추지 않는다.
   - 기준 완화·공개 배포·새 외부 서비스·비용·보안 규칙 변경은 사용자 결정으로 넘긴다.
4. 사용자 결정이 필요하면 **질문은 한 문장, 선택지는 2개**로 적고, 답을 기다리는 동안 다른 줄(레인)의 일을 계속한다.
5. 이미 지시서에 답이 있는 사항(파일 경로, 승인된 전송, 정해진 기준)을 다시 묻거나 "찾지 못했다"고 보고하기 전에 지시서와 `git log -5 --stat`, 해당 폴더 목록을 확인한다.

## 2. 병렬 작업 (레인)

독립적인 일은 보조 에이전트에게 나눠 동시에 진행한다. 레인마다 **수정할 수 있는 파일이 정해져 있고**, 두 레인이 같은 파일을 고치지 않는다.

| 레인 | 맡는 일 | 수정 범위 |
| --- | --- | --- |
| A 편향 연구 | 라벨 합의, 재학습, 좌표·기준선, 진단 | `research/`, `scripts/*voice*`, `.sites-runtime/`, `docs/test-runs/` |
| B 링크·추출 | 가져오기, 본문 추출, robots, 포털 | `lib/server/retrieval*.ts`, `lib/server/open-retrieval.ts`, `lib/server/article-*.ts`, 해당 테스트 |
| C 화면 | 안내 문구, 탭 전환, 편향 보조 표시 | `components/`, `app/` 화면 파일, 해당 테스트 |
| D 검증 | 실제 링크 점검, 측정, 리뷰(읽기 전용) | `scripts/check-*.mjs`, `docs/test-runs/` |
| 통합(주 에이전트) | 공용 파일, 합치기, 최종 검증, 커밋 | `lib/contracts.ts`, `lib/server/analyze*.ts`, `lib/server/analysis-cache.ts`, `AGENTS.md`, 상태 파일 |

- 공용 파일을 바꿔야 하는 레인은 변경 요청을 통합 담당에게 넘긴다(필요한 필드·타입을 3줄로).
- 보조 에이전트에게 주는 지시는 자체 완결로 쓴다: 목표, 수정 가능 파일, 완료 기준, 실행할 검사, 금지 사항, 보고 형식(5줄).
- 오래 걸리는 일(임베딩, 라벨링, 학습)은 백그라운드로 돌리고 그동안 다른 레인을 진행한다. 끝나기를 기다리며 멈추지 않는다.
- 보조 에이전트 수는 한 번에 3개 이하. 레인이 하나뿐인 일에는 쓰지 않는다.

## 3. 반복 절차는 고정 명령(스킬)으로

같은 절차를 매번 새로 짜지 않는다. 아래를 `package.json` 스크립트로 만들고(이미 있으면 그대로 쓰고), 지시서와 보고에는 이름만 적는다.

| 이름 | 하는 일 |
| --- | --- |
| `check:quick` | 타입 검사 + 변경된 파일과 관련된 테스트만 |
| `check:full` | 타입 검사 + 전체 테스트 + 빌드 + `git diff --check` |
| `start:research` | 연구 모델 주입 빌드를 정해진 포트로 실행 |
| `check:links` | 실제 링크 점검 스크립트(opt-in, 결과 JSON 저장) |
| `bias:diagnose` | 탈락 단계·분포·판별률 진단(API 0회) |
| `bias:retrain` | 합의 라벨 → 준비 → 학습 → 평가 → 보고서 |

Codex의 스킬 기능을 쓸 수 있으면 위 여섯 가지를 스킬로 등록한다. 없으면 스크립트로 충분하다.

## 4. 검증과 기록

- 작업 중에는 `check:quick`만. `check:full`은 **회차 끝에 한 번**, 막힌 항목이 있어도 실행한다.
- 한 번 확인한 사실(공개 사이트 모델, 한도 값, 파일 위치)은 상태 파일의 "확인된 사실" 표에 날짜와 함께 한 줄로 적고 다시 확인하지 않는다. 값이 바뀔 이유가 생겼을 때만 재확인한다.
- 상태 파일은 레인별 하나(`BIAS_STATUS.md`, `LINK_FETCH_STATUS.md`). 맨 위에 "목표·완료 여부·막힌 것·다음 할 일" 표만 두고, 지난 회차 기록은 `docs/archive/`로 옮긴다. 200줄을 넘기지 않는다.
- 수치는 `docs/test-runs/*.json`에, 문서에는 핵심 숫자와 파일 이름만.
- 한계·주의 문구는 항목당 한 번만 쓴다. 같은 단서("사람 정확도 아님")를 문단마다 반복하지 않는다.

## 5. 커밋과 보고

- 레인이 끝날 때마다 커밋한다(레인당 1개). 전부 끝날 때까지 쌓아 두지 않는다. 막힌 항목이 있어도 끝난 부분은 커밋한다.
- 회차 보고는 10줄 이내: 끝낸 것 / 못 끝낸 것과 이유 / 사용자 결정 필요 / 다음 회차 첫 작업.
- 공개 배포와 GitHub 푸시는 기존 규칙대로 사용자 확인 뒤.

## 6. Claude와의 분담

- 화면 확인, 공개 사이트 점검, 계획 검토는 Claude가 한다. Codex는 화면 도구가 안 되면 재시도하지 않고 `.sites-runtime/CODEX_TO_CLAUDE.md`에 주소·포트·확인 항목을 적는다.
- Claude의 지시서에 사실 오류가 있으면 근거와 함께 상태 파일에 적고, 고친 방식으로 진행한다(멈추지 않는다).
