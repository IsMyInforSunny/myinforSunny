# 내 정보 맑음? — 기술명세 v3.0

2026-10-30 · 현재 기준. 외부 생성 AI API 중심 v2.0을 대체합니다. 개발계획 v3.0·아키텍처 v3.0과 함께 적용합니다.

## 1. 시스템 계약

사용자 브라우저에서 사전학습 encoder와 팀이 학습한 분류기를 실행하는 미디어 리터러시 도구입니다. 본문·댓글·선택 명제·선택 주장·입력 자료를 처리합니다. 입력을 외부 AI API로 보내지 않습니다. 개발자 PC의 상시 서버 실행을 요구하지 않습니다.
현재 화면과 학습용 예시는 구현돼 있지만, 실제 운영 모델은 준비 중입니다. 아래 모델 경로는 구현 목표이며 각 모듈의 실제 완료 상태는 implementation-status.md에 별도로 기록합니다.

## 2. 입력·원문·상태

- 본문 최대 8,000 UTF-16 코드 단위, 댓글 최대 30개·각 500, 선택 명제 200, 선택 주장 최대 3개, 참고자료 최대 5개·각 8,000.
- 원문은 정규화하지 않고 보존합니다. 분석용 문자열 정규화는 별도 복사본에 적용하며 모델의 토큰 위치를 곧바로 원문 위치로 사용하지 않습니다.
- Span은 sourceId/sentenceId/start/end/quote이며 `original.slice(start,end)===quote`를 만족해야 합니다. 이모지·동일 문장 반복을 검사합니다.
- 실행 상태: demo / model_loading / model_unavailable / running / partial / success / failed / cancelled. 모델이 없으면 예시로 임의 입력 결과를 대신하지 않습니다.
- 결과마다 engineVersion, taskModelVersion, encoderRevision, rubricVersion, preprocessingVersion, inputVersion을 남깁니다. 예시·합성 모델·운영 모델을 구별합니다.

## 3. 과제별 모델

| 과제 | 입력/출력 | 학습·판정 규칙 |
|---|---|---|
| 표현 | 문장과 문맥 → clear/flagged/undetermined 및 하위 기준 | 1차 이진 baseline 이후 기준별 multi-label. 인용·반어·부정·맥락 부족 별도 평가 |
| 논점 | 명시한 주제 범위의 댓글 → 여러 topicId 또는 other/undetermined | 고정 논점 사전·다중 라벨 head. open-domain 발견은 별도 기능 |
| 입장 | 명제+댓글 → support/oppose/mixed/not_expressed/undetermined | 감정 극성·코사인 유사도로 대체 금지. 쌍 입력 encoder 형식 고정 |
| 주장 후보 | 문장 → factual/opinion/undetermined 후보 | 사용자가 확인·수정. 추출 누락을 표시 |
| 근거 관계 | 주장+자료 문장 → supports/contradicts/context/insufficient | 임베딩은 후보 검색만. 관계 head 별도 학습, 시점·대상·수치 검사 |

사전학습 encoder는 후보를 한국어 자료로 평가한 뒤 model ID·revision·license·tokenizer·pooling·최대 토큰·정규화를 model card에 고정합니다. 특정 모델의 성능을 검증 전에 확정하지 않습니다. Python과 브라우저의 토크나이저·pooling이 다르면 같은 head를 사용할 수 없습니다.
SVM의 margin은 확률이 아닙니다. 이진 head는 `w·((x-mean)/scale)+b`, 확률이 필요하면 독립 calibration 자료로 학습한 sigmoid를 적용합니다. 다중 라벨 보정은 각 head별로 수행하고 합이 1이라고 가정하지 않습니다. 다중 클래스는 해당 보정법을 별도 검증합니다.

## 4. 세 항목의 수치와 설명

1. 논점 언급률 = 해당 논점이 배정된 댓글 수 / 제출 댓글 수. 다중 배정으로 합계가 100%를 넘을 수 있습니다. 단일 본문만 있을 때 여론 비율을 만들지 않습니다. 유보 댓글 수와 모델의 학습 범위를 표시합니다.
2. 표현 검토 비율 = flagged 문장 수 / 전체 입력 문장 수. 미처리·불확실 문장은 undetermined로 표시하고 별도 집계합니다. 이 비율을 사람의 공격성 확률이라고 부르지 않습니다.
3. 자료 뒷받침률 = supported 주장 수 / 정상 대조 완료 주장 수. 대조 진행률 = 정상 대조 완료 수 / 추출·확인한 사실 주장 수. supported/contradicted/conflicting/insufficient/unchecked/inaccessible/not_applicable를 분리합니다. 분모 0은 null입니다.

인용·자료 관계는 모델 결과와 함께 원문 근거를 보여 줍니다. 전체 문장을 분류했으면 전체 문장을 근거로 표시하고, 실제로 검출하지 않은 단어를 원인이라고 강조하지 않습니다. 선형 특징 기여는 해당 특징 공간에 대한 설명이며 사람의 심리·인과 설명이 아닙니다. 생성형 자연어 설명은 필수 의존성이 아니며 기준별 정형 설명을 사용합니다.

## 5. 데이터 계약

JSONL 공통 필드: id, group, text, task, label, split(train/calibration/dev/test), provenance, license, annotationStatus(draft/reviewed/adjudicated), reviewers, rubricVersion. embedding 경로는 embedding 배열과 embeddingVersion이 필요합니다.
문맥·명제·자료 쌍 과제는 별도 필드를 두고 encoder 입력 포맷을 버전 관리합니다. 단일 표현 분류 JSON을 다른 과제의 학습 자료로 재해석하지 않습니다.
reviewed/adjudicated 자료만 평가에 사용하며 최소 두 명의 독립 검토 이력 또는 공개 자료의 검증 가능한 원래 라벨 계보가 필요합니다. 계정 ID가 두 개 있다는 사실만으로 독립성을 증명하지 않으므로 실제 기록을 검토합니다. AI 초안·팀 예시는 draft 또는 synthetic으로 남깁니다.
문서 그룹과 중복 텍스트의 분할 누수를 차단합니다. 임베딩의 모델 revision과 차원·finite 값을 검사하고 서로 다른 encoder 결과를 섞지 않습니다.

## 6. 학습·평가·배포 artifact

Python 학습: train에서 특징 변환·head fit → calibration에서 sigmoid fit → dev에서 모델/유보 임계값 선택 → 모델·설정 동결 → test 평가. PCA fit도 train 또는 명시한 탐색 코퍼스에만 수행합니다. 시험셋으로 재학습·보정하지 않습니다.
artifact에는 schemaVersion, task, labels, encoderVersion, dimension, scaler mean/scale, linear weights/bias, calibration coefficients, abstain thresholds, dataset hash, split hashes, configuration, model card 상태를 포함합니다. 원문 학습 자료와 개인 정보를 공개 artifact에 넣지 않습니다.
운영 승격은 사람 검토·test 보고서·브라우저 parity·지연·메모리·라이선스 확인 후 수행합니다. 합성 시험 artifact는 production으로 승격하지 않습니다. 모델의 JSON 직렬화는 pickle 실행 위험을 피하고, 로딩 시 크기·차원·finite·버전을 검증합니다.
평가 보고서: 클래스별·macro-F1, confusion matrix, coverage, abstention, 전체 기준 성능, 보정 Brier/ECE, 오류 유형, p50/p95 지연·메모리·다운로드 크기. 숫자가 없으면 미측정이라고 표시합니다.

## 7. 브라우저 실행

정적 모델 manifest → 해시·크기 확인 → encoder와 head 로드 → Web Worker 초기화 → 원문 문장화 → 임베딩·head 추론 → 유보·근거 검사 → 지표 계산 → 화면 표시.
WASM CPU 경로를 기본 호환성 후보로 두고 WebGPU는 선택 가속입니다. 대형 모델은 사용자 동의 후 다운로드하며 진행률·취소·용량을 표시합니다. 모델 파일 캐시와 사용자 원문 저장은 분리합니다. 탭을 닫으면 원문·결과는 사라지고 사용자 선택 내보내기만 로컬 파일로 저장합니다.
메모리·WebGPU·다운로드 실패 때는 오류 또는 준비된 경량 모델을 명시적으로 선택하도록 하며 외부 AI로 전송하지 않습니다. 처리 중 입력이 바뀌면 inputVersion으로 이전 결과를 구분합니다.
현재 `/api/analyze`와 `/api/verify`는 예시 호환용으로 유지할 수 있으나 실제 사용자 글의 외부 inference를 중단합니다. 최종 브라우저 전용 경로는 이 두 API 없이 실행 가능해야 합니다. 모델 manifest 조회는 정적 파일 다운로드이며 AI API 호출이 아닙니다.

## 8. 자료 대조·출처

최초 범위는 사용자가 붙여 넣은 자료입니다. 유사 문장 검색 결과는 미대조 후보로 표시하고 모델의 관계 검증 전 supported로 승격하지 않습니다. URL 본문 자동 취득·웹 검색은 기본 미연결입니다. 후속 연결 시 실제 취득 본문·시각·발행 시점·실패를 보존하고 브라우저 CORS 문제를 무단 프록시로 우회하지 않습니다.
사실 주장 선택·검토 기능은 필수이며 범용 자동 추출 모델이 완성될 때까지 사용자 확인 방식으로 진행합니다. 근거 관계 head 미준비 상태는 unchecked로 유지합니다. 자료 없음은 거짓이 아닙니다.

## 9. 개인정보·비용·수용 기준

외부 AI 키 요구·AI inference fetch·결제·유료 fallback 없음. 원문은 브라우저 메모리에서만 처리하며 자동 학습·로그 저장 금지. 모델 파일 취득 호스트는 콘텐츠 제공에만 사용하며 분석 원문을 URL·헤더·본문으로 전달하지 않습니다.
무료 호스팅의 대역폭·파일 크기·캐시·라이선스는 배포 전 실측합니다. GitHub Pages 이관은 정적 빌드 경로 검증 후에만 완료로 표시합니다.
수용 기준: 세 과제별 동결 평가, 정확한 인용·분모, 부족한 모델은 유보, Python/JS head 점수 허용오차 1e-5 이내(양자화 encoder는 별도 허용오차), 새 입력의 이전 결과 구별, 모바일 실패·취소 처리, 개발자 PC 종료 후 공개 사용 확인. 모델 없는 예시 성공으로 수용 기준을 대신하지 않습니다.
