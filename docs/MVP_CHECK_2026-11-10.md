## 차단 문제 (먼저 고칠 것)

1. **실제 기사 분석 실패.** 뉴스 본문은 327자 5문장도 `INVALID_MODEL_OUTPUT`으로 끝나고, 짧은 가상 글은 성공한다. 실패 요청 ID: `becc61fd-3aec-45ad-beaa-d10562414f93`(1,183자), `a7c4f177-0a70-44bc-82ae-8cc35ac47c17`(327자). 원인은 확인하지 못했다. 추정 후보는 출력 토큰 한도, 따옴표가 든 인용의 위치 검증, 숫자가 많은 문장의 스키마 검증이며 서버 로그로 확인이 필요하다.
2. **기사 링크 입력 거부.** 공개 환경의 `ALLOWED_RETRIEVAL_HOSTS`에 시험한 세 매체가 없거나 목록이 비어 있다. 문서에 공개 목록이 기록돼 있지 않고, 화면에도 지원 매체가 안내되지 않는다. 기본 입력 방식이 실제로 쓸 수 없는 상태다.

## 원인 조사: 실제 기사 `INVALID_MODEL_OUTPUT`

결론(높은 확신, 공급자 원문 오류 메시지로는 미확인): **출력 토큰 상한 2,000에 걸려 JSON이 끝나기 전에 잘리고, Groq 엄격 스키마 검사가 실패한다.**

- 화면 문구 "AI가 완전한 분석 형식을 만들지 못했습니다. 입력을 줄이거나…"는 `lib/server/providers/groq.ts:38`에서만 나온다. Groq가 HTTP 400 `json_validate_failed`를 돌려준 경우다. 앱은 Groq의 원래 메시지를 버리므로 "토큰 초과"라는 문구 자체는 확인하지 못했다.
- 같은 호출은 `max_completion_tokens: 2000`, `reasoning_effort: 'low'`다(`groq.ts:7,30`). gpt-oss의 추론 토큰도 이 상한 안에서 쓰는 것으로 보인다(공급자 문서 재확인 필요).
- 대조 실험(공개 버전36, 같은 프레시안 기사):

| 입력 | 문장 | 결과 |
| --- | ---: | --- |
| 가상 학교 글 96자 | 2 | 200 성공 |
| 프레시안 기사 2문장 125자(숫자·따옴표 포함) | 2 | **200 성공** |
| 프레시안 기사 앞 5문장 327자 | 5 | 502 `INVALID_MODEL_OUTPUT` |
| 프레시안 기사 1,183자 | 12 | 502 `INVALID_MODEL_OUTPUT` |

  숫자·따옴표가 든 같은 기사 문장도 2문장이면 성공하므로 내용이 아니라 **분량**이 원인이다.
- 성공한 2문장 응답을 모델 출력 형태로 되돌려 프로젝트 토크나이저(o200k_harmony)로 세면 **약 880토큰**이다. 추론 토큰은 빠진 값이다. 같은 문장 인용이 주제 근거·주장 원문·질문·반론 근거에 4번 반복되고, 반론 2개(본문·이유·필요 근거)와 주장 재서술이 큰 몫을 차지한다. 문장이 늘면 주제·주장(각 최대 5개)과 인용이 함께 늘어 5문장에서 상한 2,000에 닿는 것과 맞는다.
- 지금까지 "실제 분석 성공" 기록(11-03 버전29 등)은 모두 2문장 가상 글이었다. 화면은 본문 2,000자·24문장까지 받는다고 안내하지만 실제로는 기사 4~5문장 이상에서 실패한다.

### 고칠 방향 (선택 필요)

1. **출력 줄이기(권장, 한도 규칙 변경 없음):** 인용 `quote`를 문장 ID만 쓰거나 짧은 구절로 제한하고, 반론·질문·주제 설명 길이와 개수를 긴 글에서 줄인다. 서버는 문장 ID로 원문 위치를 이미 알고 있다.
2. **나눠 분석:** 4문장 안팎으로 나눠 여러 번 호출한 뒤 합친다. 호출 수와 대기 시간(분당 한도)이 늘어난다.
3. **출력 상한 올리기:** AGENTS.md의 모델 예약 6,500·60초 7,000토큰 보호 규칙과 충돌하므로 사용자 승인이 필요하다.
4. 공통: Groq 400 응답에서 원문 없이 `failed_generation` 길이·종료 사유만 기록해 다음 원인 확인을 쉽게 한다.
