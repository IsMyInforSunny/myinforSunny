# 상대 기준 구현 계획 · 2026-11-12 (Codex 작업용)

사용자 결정: 절대 점수(문장 수 기준)를 보완하는 상대 기준을 세 가지로 만든다. **매체를 평가하는 기준은 제외한다.**

1. 같은 사건을 다룬 다른 기사와 비교
2. 같은 주제 기사들 속 순위
3. 같은 형식끼리 비교

## 하지 않는 것

- 매체별 평균·순위·"이 매체 평소보다" 표시를 만들지 않는다. 매체 이름이 붙은 점수는 화면·내보내기·문서 어디에도 내지 않는다.
- 매체 정보는 두 곳에서만 내부적으로 쓴다: (a) 한 매체 기사가 비교 집합을 지배하지 않도록 매체당 같은 비중을 주는 가중, (b) 비교 집합 구성 공개("4개 매체 기사 n건").
- `politicalLabel`은 계속 `null`이다. 사람 평가·정확도 수치를 만들거나 주장하지 않는다.
- 새 기사 수집, 유료 서비스, 토큰 보호 한도 변경은 이 계획에 없다.

## 공통 원칙

- **같은 방법으로 잰 값끼리만 비교한다.** 입력 기사 점수와 비교 분포는 같은 코드·같은 버전·같은 분석 범위(현재 앞 2,000자)로 계산한다. 규칙 기반 값과 LLM 기반 값을 섞어 순위를 내지 않는다.
- 분포 파일에는 본문·제목·URL을 넣지 않는다. 주제·형식별 건수와 백분위 경계값만 담는다. 원문은 계속 `.sites-runtime/`에만 둔다.
- 비교 집합이 작으면 순위를 내지 않고 "비교 기사 부족"으로 표시한다. 기준은 아래 각 단계에 적었다.
- 화면에는 항상 절대 점수, 상대 위치, 비교 집합(주제·형식·건수·수집 기간), 기준 버전을 함께 보여 준다.

## 선행 조건 (이미 요청한 항목)

- 실시간 분석 엔진을 Groq로 되돌리고 출력 분량을 줄여 실제 기사 분석이 끝까지 되게 한다(`MVP_CHECK_2026-11-10.md` 원인 조사 절).
- 공개 `ALLOWED_RETRIEVAL_HOSTS`를 고쳐 기사 링크 입력이 되게 한다.

이 둘이 안 되어도 1단계의 오프라인 작업은 먼저 진행할 수 있다.

## 1단계 — 같은 주제 기사들 속 순위 (가장 먼저)

대상 지표는 AI 호출 없이 규칙으로 계산되는 두 가지다.

- 자극 표현 탐색: `fomo-lexical` 규칙의 검출 문장 / 전체 문장
- 근거 출처 명시: `lib/cited-sources.ts` 규칙의 이름 있는 출처가 연결된 문장 비율

작업:

1. `research/` 아래 오프라인 스크립트를 만든다. `articles-reviewed-3000.local.jsonl`을 읽어 각 기사에 사이트와 **같은 모듈**로 두 지표를 계산한다(문장 분리 `sentence-3.1`, 앞 2,000자 범위 동일).
2. 주제(6개)별로 건수와 백분위 경계값(5%p 간격)을 계산한다. 매체당 같은 비중이 되도록 가중한다.
3. 결과를 `lib/data/relative-baselines.json`에 저장한다. 포함: 버전, 지표 규칙 버전, 수집 기간, 주제별 n, 경계값. 본문·URL·매체별 값은 넣지 않는다.
4. 사이트에서 입력 기사의 주제를 기존 주제 키워드 규칙으로 찾고, 같은 지표의 백분위를 표시한다. 예: "자극 표현 12점 · 같은 주제 기사 550건 중 상위 20%".
5. 주제를 찾지 못하거나 주제 n이 100 미만이면 순위를 숨긴다.

완료 기준: 6개 주제 분포 파일 생성, 같은 기사를 스크립트와 사이트에서 계산한 값이 일치하는 테스트, 화면 표시, `typecheck`·`test`·`build` 통과.

LLM 기반 점수(표현 검토·입장)의 순위는 이 단계에서 만들지 않는다. 같은 프롬프트 버전으로 3,000건을 분석한 분포가 생긴 뒤에만 추가한다(별도 결정, 토큰 예산 필요).

## 2단계 — 같은 형식끼리 비교

1. 형식 분류기를 규칙으로 만든다: 보도 / 사설·칼럼·기고 / 인터뷰 / 기타. 단서는 제목 머리말(`[사설]`, `[칼럼]`, `[기고]`, `[인터뷰]` 등), 수집 행의 `section`, 본문 서두 패턴이다. 단서가 없으면 "형식 미확인"으로 둔다. LLM 판정은 쓰지 않는다.
2. 1단계 스크립트가 주제×형식별 분포도 함께 계산한다.
3. 입력 기사의 형식이 확인되고 해당 주제×형식 n이 30 이상이면 같은 형식 분포로 순위를 낸다. 아니면 주제 전체 분포로 내고 "형식 구분 없이 비교"라고 표시한다.
4. 사설·칼럼으로 분류된 글에는 "의견을 펴는 형식의 글"이라는 안내를 붙인다. 편향 점수를 깎거나 바꾸지 않는다.

완료 기준: 3,000건의 형식별 건수 보고(미확인 비율 포함), 분류 규칙 테스트, 주제×형식 분포 반영, 화면 표시.

## 3단계 — 같은 사건을 다룬 다른 기사와 비교

1. 사건 묶음 만들기(오프라인): 같은 주제 안에서 발행일이 ±3일 이내이고 제목·본문 핵심어 유사도가 기준 이상인 기사를 한 사건으로 묶는다. 유사도 기준은 표본을 보고 정하고 문서에 기록한다.
2. 적격 조건: 사건 묶음에 서로 다른 매체 2곳 이상, 기사 3건 이상(현재 최소 기준 유지). 미달이면 "같은 사건 비교 기사 부족"이다.
3. 사건 색인 파일에는 사건 ID, 주제, 기간, 건수, 지표 요약만 담는다. 추천 링크를 보여 줄 때 쓰는 제목·URL 목록은 이용 조건 검토 전이므로 공개 저장소에 넣지 않고 로컬 실행에서만 쓴다.
4. 사이트: 입력 기사를 같은 방법으로 사건 묶음에 대응시키고, 그 묶음 안에서 1단계 지표의 위치를 보여 준다. 예: "같은 사건 기사 5건 중 자극 표현이 가장 많음".
5. 실시간 검색(GDELT)으로 비교 기사를 모으는 경로는 검색이 안정된 뒤 별도 단계로 한다.

편향의 상대 위치(SVM 좌표와 중간 거리, 반대편 기사 추천)는 AI 입장 라벨로 학습한 모델이 자동 점검을 통과한 뒤 이 사건·주제 묶음 위에 올린다. 모델 승인 조건 변경은 사용자 결정 대기다.

완료 기준: 3,000건의 사건 묶음 수·적격 묶음 수 보고, 묶음 규칙 테스트, 적격 사건에서 화면 표시, 부족 상태 표시.

## 검증과 보고

- 각 단계 끝에 `npm run typecheck`, `npm test`, `npm run build`를 실행하고 결과를 `docs/`에 기록한다.
- 오프라인 스크립트 결과(건수·분포 요약)는 `docs/test-runs/`에 집계만 저장한다.
- 공개 배포는 사용자 확인 뒤에 한다.
- 분석 기준 페이지(`/methodology`)에 비교 집합의 한계를 적는다: 4개 매체, 6개 주제, 수집 기간 2024-01-01~2026-11-04, "인터넷 뉴스 전체"가 아님.
