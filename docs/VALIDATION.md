# 검증 기록과 출시 기준

## 기록을 읽는 원칙

아래는 과거 실제 실행 기록이다. 이 문서를 작성하거나 GitHub에 푸시하는 행위가 모든 시험을 재실행했다는 뜻은 아니다. 코드 변경 이후 관련 검사를 다시 실행하고, 새 실패가 있으면 기존 성공과 함께 남긴다.

| 범위 | 확인된 기록 | 의미 |
|---|---|---|
| 배포 13 기준 | 타입·빌드, 회귀 172개 통과, Sites 배포 성공 | 해당 소스의 배포·기능 검사 |
| 실제 Groq 본문 분석 | 가상 기사 1건 성공, 3,869토큰, 논점 2·사실/의견 주장 2·본문 배정 | 소규모 선별 시험. 독립 정확도 아님 |
| 배포 13 브라우저 | 본문만/댓글 분리, 375px 결과 이동·초점·가로 넘침, 세 페이지 오류 검사 | 해당 배포의 검사 구간 |
| 최신 로컬 회귀 | 최근 실행 184개 통과 | 모의 제공자·가상 자료 중심 |
| 출처·추출·조사 재검사 | 3개 파일의 16개 통과 | 인용·연결·추출 계약 검사 |
| 실제 Groq 대조 | 상충 기대값 대신 insufficient가 나와 실패, 1,983토큰 기록 | 원인 확인·원출력 보존·재검증 필요 |
| 사람 평가 | 가상 40사례·평가자 2명 양식·비교 도구 | 라벨·정답 비교·효과 검증 미완료 |

최신 코드를 설치한 환경에서는 다음으로 현재 결과를 확인한다.

```sh
npm run typecheck
npm test
npm run build
```

기본 시험은 실시간 API를 자동 호출하지 않는다. 실제 opt-in 시험은 키·계정 조건·무료 예산을 확인하고 따로 실행한다. 로컬 런타임/D1 통신 권한 실패와 실제 코드 실패를 구분한다. 시험 개수만으로 분석 정확도를 표시하지 않는다.

## 주요 회귀 범위

- 소수점·날짜·인용·이모지·반복 문장·긴 문장 위치.
- 본문 완전 배정, 다중 논점, 누락·중복·유보, 본문/댓글 분모 분리.
- 사실 주장과 의견 분리, 원문 인용 일치, 자료 관계·반복 인용 위치.
- 서버 secret 비노출, 서명 위조·다른 IP·입력 변경·만료 거절.
- 무료 토큰 예약·동시성·요청 제한, 검색 IP·월간 원자적 제한.
- HTML 본문·숨김/메뉴 제외, 한글 인코딩, 크기·콘텐츠·리다이렉트 제한.
- 의견만 있는 글 탐색, 모델 대기·검색 대기·취소·자료 없음과 부분 결과.

## 출시 게이트

1. 출처 선정·원자료·전재 계보·통계 범위 기준을 구체화한다.
2. 시점 지시 충돌과 추천/대조 기준 차이를 수정한다.
3. 실제 대조 실패 원인과 새 추출기 Worker 빌드를 확인한다.
4. 사용자 승인 후 검색 계정·조건·무료 한도·허용 출처를 설정한다.
5. 실제 검색→본문 취득→대조→관련/다른 관점 추천을 검증한다.
6. 429·실패·취소·부분 상태·모바일·예산 소진·예시 전환을 확인한다.
7. 독립 사람 평가를 수행하고 문서·화면·배포 상태를 맞춘다.

기본 기준을 통과하지 못하면 자동 검색을 켜거나 미확인 정확도 수치를 게시하지 않는다. PDF와 과거 문서는 시점별 설명 자료이며 최신 실행 결과를 대체하지 않는다.
