# 기술명세 — 현재 구현과 출시 요구사항

기준일 2026-10-31. 공개 배포 13과 이후 로컬 개발을 함께 설명한다. GitHub 업로드는 새 Sites 배포·자동 검색 활성화를 의미하지 않는다. 기본 원칙은 무료 운영, 실제 원문 인용, 불확실성 표시, 입력 비저장, 사람이 최종 판단하는 것이다.

## 1. 기능과 입력

본문은 2,000자, 댓글은 최대 5개×200자, 선택 명제는 160자다. 총 처리 단위 24개를 넘으면 분석 전 거절한다. 자연 문장과 처리 조각은 다르다. 긴 문장은 약 500 UTF-16 단위로 분할하며 끝 문장부호 최대 8개 예외를 둔다. `sentence-3.1`은 소수점·날짜·인용·이모지와 공백 위치를 보존한다. 구간이 바뀐 이전 분석으로 자료 대조를 시도하면 재분석을 요구한다.

본문 논점 분포는 `bodyTopicAssignments`로 모든 본문 처리 단위를 배정한 뒤 자연 문장으로 합친다. 댓글 분포는 별도다. 누락·중복·알 수 없는 논점 ID는 유보/부분 결과로 처리한다. 논점 대표 인용의 개수를 전체 분포로 사용하지 않는다.

표현 기준은 personal_attack, group_generalization, mockery, fear_appeal, overstatement, threat다. 인용·풍자·모호한 맥락을 구분한다. 긴 문장의 여러 조각이 표시돼도 자연 문장 수는 중복 집계하지 않는다. 표현 표시와 일부 판단 유보가 겹칠 수 있다.

확인 가능한 수치·사건·인용 주장은 근거가 없더라도 factual 유형으로 추출한다. 이는 참이라는 뜻이 아니다. 의견은 opinion, 유형 자체가 불명확하면 undetermined다. 논점·주장은 최대 5개이며 추출 누락 가능성을 표시한다.

## 2. 3축과 결과 표시

| 축 | 집계 | 금지·한계 |
|---|---|---|
| 논점 분포 | 각 논점 자연 문장 수 / 전체 본문 자연 문장 수; 댓글은 별도 | 다중 배정 합계가 100%를 넘을 수 있음. 여론·중요도 점수 아님 |
| 자극성 | 표시된 자연 문장 수 / 전체 자연 문장 수, 유보 건수 | 공격성 확률·안전성 인증 아님 |
| 신뢰성 | 대조 완료·미확인·뒷받침·상충·불충분과 실제 자료 수 | 기사 전체 진실 확률·언론사 점수 아님 |

분모 0은 ‘해당 없음’, 분모 10 미만은 퍼센트 대신 건수 중심이다. 헤드라인·요약·상세는 최신 대조 결과와 같은 집계 함수를 사용한다. 원문은 `slice(start,end) === quote`로 검사하고 선택한 문장 위치를 보존한다. 이 검사는 해석 정확도를 보장하지 않는다.

## 3. API

| 메서드·경로 | 입력과 결과 |
|---|---|
| POST /api/analyze | demo fixture 또는 text·comments·동의 → Analysis |
| POST /api/verify | demo 또는 선택 사실 주장 1개·자료 최대 2개×1,500자 → Verification |
| POST /api/research | plan/discover/compare + 원문·대상·조사/전송 동의. 운영 게이트 필요 |
| POST /api/news | 검색어·검색 동의 → 확인되지 않은 기사 후보 |
| GET /api/capabilities | 실시간·검색·취득 상태·제한값. 키 반환 금지 |
| GET /api/health | 런타임 상태. 정확도 인증 아님 |

JSON 외 요청, 다른 Origin, 과도한 요청 본문, 잘못된 형식은 거절한다. 모델 원문 오류·제공자 메시지·입력 내용을 응답이나 로그로 그대로 노출하지 않는다.

## 4. 데이터 계약

`Analysis`는 schemaVersion 2.1, versions, sources, topics, bodyTopicAssignments, topicAssignments, expressions, claims, indicators, coverage, warnings를 포함한다. `Span`은 sourceId·sentenceId·start·end·quote이며 실제 원문 구간과 일치해야 한다. `Check`는 claimId·outcome·execution·relations·temporalFit·limitations다.

outcome은 supported/contradicted/conflicting/insufficient/unchecked/inaccessible/not_applicable이며 execution은 completed/failed/skipped로 의미를 분리한다. 최신 검사 실패를 과거 성공으로 덮어 요약하지 않는다.

`Reference.provenance`는 provided_text와 web_fetched를 구분한다. 입력에 URL이 있다는 이유만으로 웹 취득 자료로 승격하지 않는다. `ResearchPlan`은 검색 목적·대상·만료·서명을, `EvidenceBundle`은 취득 자료·실패 이유·입력 해시 바인딩을 가진다. `Recommendation`은 실제 URL·제목·역할·이유·인용 위치를 가진다.

## 5. 자동 조사·추천

plan은 사실 주장마다 조사 검색어를 만들고 별도 의견이 있으면 관점 검색어도 만든다. 로컬 최신 계약은 사실 주장 0개라도 의견이 있으면 허용한다. discover는 서명된 검색어만 사용하고 허용 호스트의 자료를 최대 2개 취득한다. compare는 입력 해시·호출자·만료·서명을 확인한 뒤 모델이 선택한 자료 문장 ID로 인용을 복원한다.

취득 본문은 최대 8,000자 보유, 대조 발췌는 최대 1,500자다. 서명은 암호화가 아니며 자료는 브라우저 메모리에 둔다. 새로운 모델 호출 사이 약 61초, 검색 사이 최소 간격과 분당 상한을 지킨다. 공급자 실패를 자동 재시도하지 않는다. 자료 없음·취소·부분 완료를 전체 성공으로 표시하지 않는다.

출처 없는 AI 제안, 다른 수치를 가진 자료, 명시적인 반대 의견, 관련 맥락은 서로 다르다. 실제 취득·인용 일치 없이 출처 있는 관점으로 표시하지 않는다. 기사 본문 전체를 화면에 복제하지 않고 제목·링크·짧은 발췌만 제시한다.

## 6. 제공자와 출처 선정

GDELT 경로는 최근 30일 한국어, 20건 요청, 중복 제거·도메인당 최대 2건·후보 최대 5건이다. Tavily 로컬 경로는 basic/news, 한국어 필터, 결과 최대 5건, auto_parameters=false, include_answer/raw_content/images=false다. 자동 유료 전환을 하지 않는다. 실제 Tavily 계정·허용 출처·승인은 아직 없다.

Readability+linkedom/worker는 스크립트·외부 자원을 실행하지 않고 본문 텍스트를 추출한다. 명시적 유료 접근 표시와 일부 noai/nosnippet 표기를 검사한다. UTF-8/EUC-KR을 명시적으로 처리하며 2MiB 초과·지원하지 않는 콘텐츠·리다이렉트를 거절한다. 이 기능이 모든 저작권·이용 조건의 해결을 뜻하지 않는다.

**미완성:** 원자료 우선, 동일 사건·대상·지표·시점 확인, 통계 분모·단위·표본·개정, 정정·철회, 전재 계보·독립성, 출처별 이용 조건·선정 이유를 규칙과 데이터로 구체화해야 한다. 검색 순위와 URL 개수는 출처 신뢰성의 대체물이 아니다.

## 7. 보안·예산

모델은 Groq gpt-oss-120b만 활성 제공자다. 계정 확인 기록 30 RPM/1,000 RPD/8,000 TPM/200,000 TPD와 내부 한도는 구분한다. 요청 예약 6,500·출력 2,000·60초 합계 7,000·전역 동시 1개·IP별 3/분·20/시간·일일 120,000토큰/최대 500요청이다. 계정 한도의 80%보다 커지지 않도록 계산하며 사용량을 모르면 예약을 보수적으로 유지한다.

검색은 별도 3/분·20/시간·전역 200/일. Tavily 월간 예약은 확인 크레딧의 80%, 최대 800이며 provider plan·자격·월 한도 확인이 없으면 호출하지 않는다. 이는 계정의 유료 결제를 취소하거나 과금을 통제하는 기능이 아니라 앱 차원의 호출 상한이다.

D1에는 HMAC 호출자·시각·예약·소비량·대기 상태만 저장한다. 월간 카운터에는 본문이나 검색어가 없다. 키는 서버 secret만 사용하며 실제 `.env`·파일럿 결과는 공개 저장소에 넣지 않는다. 외부 제공자 정책은 입력 비저장 안내와 별개다.

## 8. 출시 전 조건

명시적인 검색 서비스 승인, 원문 이용 조건, 실제 검색·취득·대조·추천 연결, 시간·범위 일치, 한도·취소·모바일·부분 결과, 문서 동기화와 사람 평가를 확인해야 한다. 현재 실제 Groq 가상 대조 실패 사례가 있어 정확도 검증 완료로 보고하지 않는다. [검증 문서](VALIDATION.md) 참고.
