# 이번 작업 목표와 수행 범위 · 2026-11-15 (Codex 작업용)

`docs/CODEX_COMMAND_2026-11-15.md`의 남은 작업(5~9)을 **시연 가능한 편향 점수**라는 하나의 목표로 좁힌다. 활동계획서 일정상 11월 안에 완성본과 시연 영상이 필요하므로, 목표에 직접 기여하지 않는 일은 이번 회차에서 하지 않는다.

## 이번 회차 목표 (완료 기준)

1. 우선 4개 쟁점(주택 공급·의대 정원·원전 확대·최저임금 인상)의 보관 기사 임베딩 누락 0.
2. 4개 쟁점 각각 **"전체 기간" 비교 집합이 최소 1개 적격**(구간 중앙값, 매체당 적격 기사 ≥3·매체 ≥2).
3. 로컬 사이트에서 4개 쟁점의 **실제 기사 링크 각 1건 이상**이 편향 점수(점 또는 범위)와 반대편 기사 후보를 보여 준다.
4. 화면 확인을 Claude에게 넘기고, 전체 검증 1회 통과.

정확도 작업(합의 라벨·재학습)은 목표 2가 달성된 뒤에, 범위를 좁혀 진행한다.

## 하지 않을 것 (시간 낭비 차단)

- 우선 4개 쟁점 밖의 임베딩(약 3만 문장)은 이번 회차에서 돌리지 않는다.
- 분기·반기 집합 최적화는 하지 않는다. "전체 기간" 적격이 먼저다.
- 작업마다 전체 테스트·빌드를 돌리지 않는다. 관련 테스트만, 전체는 마지막 1회.
- 속도 재측정, 캐시 재측정, 문서 추가 작성을 하지 않는다. `docs/BIAS_STATUS.md` 한 곳만 갱신한다.
- 6개 주제 전체 재학습을 하지 않는다. 4개 쟁점만.
- 화면 도구를 직접 다시 시도하지 않는다. 9번은 메모로 넘긴다.

## 수행 순서

### ① 임베딩 큐 재개 (예상 1시간 이내)
- 상태: `failed`, `stopReason: extractor_failed_or_unknown_no_retry`. 완료 10,603 / 우선 쟁점 남은 문장 **약 9,040**(의대 3,489·원전 259·최저임금 5,292, 주택은 완료).
- 마지막 요청 기록만 확인한다. 응답 벡터가 체크포인트에 있으면 완료 처리, 없으면 **그 배치 1개만** `--retry-unknown`으로 한 번 다시 보낸다. 임베딩은 같은 문장을 다시 보내도 결과가 같아 중복 전송의 피해가 거의 없으므로(NVIDIA 토큰 한도 없음), 원인 분석에 오래 쓰지 않는다.
- 남은 우선 쟁점만 실행: 약 142배치 × 20초 ≈ 48분.
- 같은 오류가 다시 나면 오류 코드·HTTP 상태만 기록하고 그 배치를 건너뛴 뒤 계속한다. 건너뛴 배치는 마지막에 한 번 더 시도한다.

### ② 쟁점 배정(작업 7) — 임베딩이 도는 동안 병행
- 동점·무근거 기사: 제목 가중 2 → 그래도 동점이면 "주 쟁점 2개" 계산. 보관 기사에는 LLM 결과가 없으므로 공통 명제 규칙은 실시간 입력 기사에만 적용한다.
- 연금 `replacement`/`fund_risk` 규칙 겹침 수정.
- 검증: 미배정 건수 변화, 바뀐 기사 20건 표 1개. 그 이상 검토하지 않는다.

### ③ 구간 중앙값 비교(작업 6) 완성 → 목표 2 측정
- ①·② 완료 후 좌표를 다시 계산하고 4개 쟁점의 "전체 기간" 적격 집합 수를 기록한다.
- **적격이 0인 쟁점이 있으면 원인 하나만 기록한다**(매체별 적격 기사 수 표). 기준을 낮추지 않는다. 원인이 "방향 문장 3개 미만 기사가 대부분"이면 그 쟁점은 이번 회차 범위에서 빼고 다음 쟁점으로 넘어간다.

### ④ 로컬 사이트 연결 → 목표 3
- 작업 4의 연구 전용 경로에 ③ 결과를 연결한다(공개 파일은 `null` 유지).
- 적격 쟁점마다 실제 기사 링크 1건으로 로컬 분석 → 점수·범위·반대편 후보가 나오는지 확인한다. 결과는 `docs/test-runs/demo-bias-2026-11-15.json` 하나.

### ⑤ 합의 라벨·재학습(작업 8) — 범위 축소판
- 처리량 한계: Groq 기록 한도 TPD 200,000·RPD 1,000. 기사 1건 라벨 호출을 약 3,000~4,000토큰으로 보면 하루 약 50건이다. 그러므로 Groq는 **합의 평가 세트 30건에만** 쓴다.
- 학습 라벨 확장의 두 번째 모델은 NVIDIA에서 쓸 수 있는 **다른 계열 모델**(토큰 한도 없음)을 우선 검토한다. 쓸 수 있는 모델과 이름은 Codex가 확인하고 `BIAS_STATUS.md`에 적는다. 없으면 Groq로 하되 하루 처리량 안에서 4개 쟁점 기사부터.
- 순서: (a) 평가 세트 재채점(정제 전/후) → (b) 합의 평가 세트 30건 → (c) 쟁점별 찬성/비찬성 예시 고정 → (d) 4개 쟁점 학습 라벨 확장 → (e) 재학습·확률 보정 → (f) LLM–SVM 이중 확인. (a)·(b)·(c)만 이번 회차 필수, (d)~(f)는 남는 시간에.
- 기준 미달이면 운영 후보로 올리지 않고 결과만 기록한다.

### ⑥ 마무리
