## 2. 발견한 문제

### 2-A. LLM 본문 입장 (지금 켜져 있는 층)

1. **발화 주체 판정의 동사 목록이 좁다.** 서버 규칙은 `lib/cited-sources.ts:74`의 `SAYING_VERB`(밝혔다·말했다·강조했다 등 15개)에 의존한다. "맞선다", "비판했다", "반발했다", "요구했다", "촉구했다", "우려를 표시했다", "예측했다"가 없어 인용문이 있어도 `unclear`로 유보된다. 균형 보도 두 건이 그래서 "발화 주체를 원문 표지로 확인하지 못해"로 끝났다.
2. **가장 편향이 의심되는 유형에서 분석이 빈다.** 한쪽 취재원만 네 번 인용하고 반대편은 "입장을 내지 않았다"로 처리한 글이 `BODY_POSITION_UNAVAILABLE`이었다. 이 글의 편향 신호는 "작성자 입장"이 아니라 "인용 균형 4:0"인데, 현재 구조는 그 숫자를 만들 자리가 없다.
3. **반어를 과도한 단정으로 센다.** 표현 스키마에 `context: irony`가 있지만 쓰이지 않았다.
4. **사실 주장 누락.** "편의점과 식당이 줄줄이 문을 닫고 있다", "소상공인연합회는 … 밝혔다", "최저임금위원회는 … 의결했다" 같은 문장이 사실 주장으로 뽑히지 않았다(8건 중 4건 0개).
5. **근거 문장 선택.** 반대 글에서 사실 서술 문장(가게 폐업)이 "작성자 근거"로 남았다. 입장 근거는 평가·제안 문장이어야 한다.

### 2-B. SVM 편향 모델 (연구 단계, 비활성)

Codex 기록의 수치를 그대로 쓴다. 해석은 Claude의 것이다.

1. **재는 대상과 이름이 다르다.** AI 라벨 46건·1,024문장 중 방향(찬·반) 문장 130개. 그중 기자 서술은 **14개(찬 13·반 1)**, 취재원 발화는 116개다. 즉 문장 SVM이 만드는 좌표 `(S−O)/(S+O)`는 사실상 **"어느 쪽 취재원 말을 더 실었나"**다. 코드는 기자/취재원 집계를 따로 계산해 두고(`summarizeVoices`의 `journalist`/`source`) 좌표에는 둘을 합친다. 화면과 문서는 이를 "편향·작성자 입장"으로 설명한다. 측정 자체는 뉴스 편향의 정당한 신호(취재원 균형)이지만, 이름을 바꾸거나 두 좌표를 나눠 보여 줘야 한다.
2. **표본이 결론을 지탱하지 못한다.** 임베딩 SVM 후보(`be2b3b35…`)의 고정 평가 149문장 중 방향 문장은 **21개(찬성 12·반대 9)**다. 찬성 재현율 0.75는 12개 중 9개다. 이 크기에서 95% 신뢰구간은 대략 0.43~0.95(이항 근사, Claude 추정)로, 기준 0.5를 넘는지조차 확정할 수 없다. 반전 쌍도 10개 중 8개다. 주제는 원전 하나뿐이다. 학습은 218문장이다.
3. **기사 단위 좌표가 0건이다.** 고정 평가 기사 7건 중 대표 좌표를 낼 수 있는 기사가 **0건**이다(`voice-embedding-status.json: primaryCoordinateAvailable 0`). 원인은 규칙이다. `mainVoiceIssue`는 기사 전체에 미확정 문장이 하나라도 있으면 `coordinate=null`, `compareVoiceCoordinates`의 적격 조건은 `unresolved===0`이다. 쟁점 헤드 유보율이 11~21%, 쟁점 F1이 0.63~0.67이라 거의 모든 기사가 걸린다. 이미 구현된 `voiceEvidenceBounds`(가능 범위)는 적격 판정에 쓰이지 않는다.
4. **쟁점을 문장마다 SVM으로 판정하는 설계가 가장 약한 고리다.** 쟁점 오류가 방향 문장 73개 중 13개(18%)이고, 쟁점 유보가 미확정의 주 원인이다. 그런데 기사의 주 쟁점은 LLM 분석과 `canonicalStanceProposition`이 이미 기사 단위로 정한다.
5. **상대 기준의 비교 집합이 존재하지 않는다.** 같은 사건(±3일, 본문 유사도 ≥0.56, 제목 ≥0.12) + 매체당 3건 + 2매체 조건으로:
   - 3,000건 전체 오프라인 색인(`event-baselines.json`): 사건 **1개**(의대 3건, 2매체). 6건 이상인 사건 0.
   - 원전 509건 실시간 매칭 진단: 쌍 매칭 6쌍, 비교 집합을 만들 수 있는 입력 **0건**.
   수집이 "주제별 매체당 750건"이었지 "같은 사건을 4매체가 다룬 묶음"이 아니었기 때문이다. 따라서 모델이 통과해도 상대 점수와 반대편 추천은 지금 자료로는 영원히 "대기"다.
6. **반전 쌍이 독립 평가가 아니다.** 10쌍 모두 같은 코퍼스(4매체) 문장이고, 8쌍은 양쪽 다 취재원 발화, 날짜 간격 30~756일이다. 같은 라벨러가 고른 쌍이라 과대평가 위험이 있다.
7. **교사 라벨이 단일 AI 1회 검토다.** Codex 1회, 사람 0건, 두 번 라벨 일치율 없음. 라벨 자체의 흔들림을 모른다.
8. **운영 경로의 지연과 한도.** 임베딩 모델은 요청마다 NVIDIA 임베딩 API를 호출한다(문장 ≤32개·6KB 배치, 10분 캐시). 비교 기사를 쓰면 호출 간격 20.1초, 분당 3회·시간당 20회 제한이 걸린다. 오늘 공개 API도 분석 3건 뒤 429가 났다. 기사 1건 + 비교 6건이면 수 분이다.
9. **이용 검토가 막고 있다.** 3,000건 모두 `pending_unapproved`이고 release 도구는 검토 기록 없이는 아티팩트를 만들지 않는다. 성능이 통과해도 여기서 멈춘다. 기술이 아니라 결정 문제다.
10. **"중간"은 4매체의 중앙값이다.** 진보 2·보수 2 매체의 동일가중 중앙값이라, 매체 구성이 바뀌면 기준선이 움직인다. 화면에 비교 매체와 건수를 항상 적어야 한다(이미 계획에 있음).

## 3. 개선안 (효과가 큰 순서)

### 3-1. 지금 자료로 편향 칸에 숫자가 나오게 하기

1. **좌표의 이름과 구성을 바로잡는다.** 화면 지표를 두 줄로 나눈다.
   - **취재원 인용 균형**: 취재원 발화 문장만으로 `(S−O)/(S+O)`. 예: "반대 쪽 인용 4문장 · 찬성 쪽 0문장".
   - **기자 서술 방향**: 기자 발화 문장만으로 같은 식. 대부분 "표명 없음"이 정상이다.
   `summarizeVoices`가 이미 `journalist`/`source`를 따로 계산하므로 표시만 바꾸면 된다. "편향 점수" 한 숫자가 필요하면 인용 균형의 중앙값 거리로 하고, 설명에 "인용된 목소리의 균형"이라고 쓴다.
2. **쟁점을 기사 단위로 고정한다.** `classifyRelativeTopic`/`canonicalStanceProposition`(또는 LLM의 `bodyPosition.proposition`)이 정한 주 쟁점 1개를 기사 전체에 적용하고, 문장 SVM의 `issue` 헤드는 "이 쟁점과 관련 있음/없음" 이진 판정으로 줄이거나 없앤다. 쟁점 유보가 사라지면 미확정이 크게 줄고(Codex 진단에서 미확정의 주 원인), 아래 3번과 합치면 기사 좌표가 나온다. 세 하위 쟁점 구분은 상세 화면의 보조 정보로 내린다.
3. **적격 조건을 "미확정 0"에서 "범위 폭"으로 바꾼다.** 이미 있는 `voiceEvidenceBounds`를 쓴다. 방향 문장 ≥3이고 가능 범위 `upper−lower ≤ 0.5`이면 좌표를 **범위로** 표시한다(예: −0.75 ~ −0.25). 미확정을 중립으로 바꾸지 않고, 점 추정 대신 구간을 그대로 보여 준다. 비교에도 구간 중앙이 아니라 "구간이 기준선의 한쪽에 완전히 놓일 때만" 방향을 말한다. AGENTS.md의 "미확정을 중립으로 치환하지 않는다"와 어긋나지 않는다.
4. **상대 기준의 1차 코호트를 "같은 사건"에서 "같은 쟁점·같은 기간"으로 넓힌다.** 같은 사건 비교는 표본이 0이므로, 먼저 3,000건 코퍼스에서 쟁점별(6주제×3쟁점) 좌표 분포를 오프라인으로 계산해 두고(매체 동일가중), 입력 기사의 "같은 쟁점 기사 n건 중 백분위"와 "중앙값 거리"를 보여 준다. 기간은 분기(90일) 단위로 나눠 시점 차이를 줄인다. 같은 사건 비교는 표본이 생기는 사건에서만 위에 얹는다. **이는 11-02에 정한 "같은 명제·같은 사건" 기준을 넓히는 것이라 사용자 결정이 필요하다.** 화면 문구는 "같은 쟁점을 다룬 4개 매체 기사 n건과 비교"로 적는다.
5. **반대편 기사 추천도 같은 코호트에서 뽑는다.** 중앙값 반대편에서 입력 좌표와 대칭인 기사를 고른다. 이용 검토 전에는 제목·매체·날짜·링크만 보여 준다(본문·인용 없음).

이 다섯 가지는 코드와 기존 자료로 가능하며 새 수집이나 API 예산이 필요 없다(4번의 오프라인 좌표 계산은 임베딩 호출 1회성 약 7만 문장 → 예산 확인 필요. 글자 TF-IDF 모델이면 호출 0회지만 성능이 낮다).

### 3-2. 모델을 믿을 수 있게 만들기

6. **라벨을 두 번 붙여 일치한 것만 학습한다.** Groq(gpt-oss)과 NVIDIA 두 모델로 같은 문장을 라벨링하고 일치율을 공개한다. 출력은 문장 번호+기호뿐이라 기사당 1회 호출이다. 불일치 문장은 학습·평가에서 빼고 비율만 보고한다.
7. **평가 표본을 늘리고 주제를 넓힌다.** 목표: 방향 평가 문장 ≥100(찬·반 각 ≥40), 주제 ≥2(원전 + 최저임금 권장: 찬반 표현이 가장 뚜렷), 반전 쌍 ≥30 중 절반은 4매체 밖 공개 문장(정부 보도자료·국회 회의록 등 권리 부담이 적은 공개 텍스트). 그래야 재현율 0.5 기준이 통계적으로 의미를 가진다.
8. **사람 라벨을 소규모로 넣는다.** 팀원 2명이 방향 문장 60개(찬·반·중 각 20)를 독립 판정 → Cohen's κ 보고. "사람 평가 0건" 상태를 깨는 가장 싼 방법이고 활동계획서의 "2명 40건"과 맞는다. 정확도 주장이 아니라 "AI 라벨과 사람의 일치도"로 쓴다.
9. **문맥 특징은 2번과 함께 채택한다.** Codex 실험에서 앞뒤 원문의 글자 특징을 합치면 방향 F1 0.60→0.65이지만 쟁점 오류가 늘었다. 쟁점을 기사 단위로 옮기면 이 부작용이 사라지므로 그때 채택한다.
10. **반전 쌍 평가를 분리한다.** 라벨러와 다른 사람(또는 다른 모델)이 쌍을 고르고, 절반은 코퍼스 밖에서 가져온다. 같은 쌍 묶음을 선택·조정에 쓰지 않는다(Codex의 inner/outer 분리는 유지).

### 3-3. 자료와 운영

11. **사건 단위 수집으로 바꾼다.** 상대 기준의 본래 정의(같은 사건)를 살리려면 "같은 날 같은 발표를 4매체가 다룬 묶음"을 목표로 수집해야 한다. 후보: 국정감사·정부 발표일·법안 처리일·최저임금위 의결일. 매체당 3건은 현실적으로 어렵다. **"사건당 매체 ≥2, 매체당 ≥1, 총 ≥4건"으로 조건을 바꿀지 결정이 필요하다.** 바꾸면 매체 가중은 매체당 1건이라도 동일가중을 유지한다.
12. **이용 검토에 선을 긋는다.** 학습과 분포 계산은 내부 연구로 두고 공개 아티팩트에는 가중치·요약 통계만 넣는다(원문·인용 없음). 추천은 제목+링크만. 이 범위로 각 매체 약관을 확인해 기록한다. 사용자 결정이다.
13. **실시간 호출을 입력 기사 1회로 줄인다.** 코호트 좌표는 오프라인에서 미리 계산해 두면 비교 기사마다 임베딩을 다시 부르지 않아도 된다. 그러면 20.1초 간격 규칙에 걸리는 호출은 입력 기사 1회뿐이다.
14. **"정치 좌우" 선택지는 모델이 생기기 전까지 숨기거나 "연구 중"으로 잠근다.** 지금은 선택해도 항상 대기다.

### 3-4. LLM 본문 입장 즉시 수정 (작은 변경, 큰 효과)

15. `SAYING_VERB`에 맞선다·맞섰다·비판했다·반발했다·요구했다·촉구했다·제안했다·호소했다·반박했다·예측했다·우려를 표시했다·내다봤다를 추가하고, 동사와 무관하게 **따옴표 + 인용 조사(라고/다고/다며/라며)** 패턴만으로도 `reported_sources`로 인정한다.
16. 한쪽 인용만 있는 기사는 `BODY_POSITION_UNAVAILABLE` 대신 `label=not_expressed, attribution=reported_sources`로 정상 반환하고, 1번의 인용 균형(예: 반대 4·찬성 0)을 함께 낸다. 편향 신호가 가장 큰 유형이므로 비워 두면 안 된다.
17. 반어는 `context: irony`를 쓰도록 지시문에 예시를 넣고, 자극 집계에서 반어는 `mockery`로 분류하거나 별도 표시한다.
18. 사실 주장 추출에 규칙 후보를 강제한다. 이미 있는 `reportedFact` 정규식(`analyze.ts:102`: 수치 + 밝혔다/발표했다/집계됐다/조사됐다)에 걸리는 문장과 인용 문장은 `claims` 후보로 모델에 넘기고, 모델이 비우면 서버가 최소 1개를 `factual`로 채운다(원문 문장 ID 연결, 새 문장 생성 없음).
19. 입장 근거에서 순수 사실 서술 문장(통계·사건 보고)을 제외하고 평가·제안 문장만 남긴다.
