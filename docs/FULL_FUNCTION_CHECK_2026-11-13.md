# 전체 기능 점검 · 공개 사이트 · 2026-11-13 (Claude)

공개 사이트 `/api/analyze`를 브라우저에서 직접 호출해 확인했다. 코드는 바꾸지 않았다. 화면(UI) 조작 검증은 이번에 하지 않았다(브라우저 창이 숨겨진 상태).

- `/api/capabilities`: `aiProvider: nvidia`, `aiModel: nvidia/nemotron-3.5-lightning-30b-a3b`, `live·webSearch·directFetch: true`, `searchProvider: publisher_feeds`, 본문 8,000자
- 실제 모델 호출: 링크 분석 4건(성공), 직접 입력 1건(성공). 나머지는 캐시 응답이다.

같은 링크 재요청은 `CACHED_ANALYSIS`로 0.1~0.5초에 돌아왔다.

## 직접 입력 시험 (가상 5문장, 전기요금 인상에 반대하는 과장된 글)

- 19.9초, 200.
- 자극: 3/5문장 검출(공포 유도 2, 인신공격 1). 기대와 대체로 일치. 3번째 문장은 집단 일반화가 더 맞다.
- **본문 입장 오류:** 명제가 "정부가 내년 전기요금을 5% 올리기로 했다"(사실 문장)로 잡혔고 label이 `support`였다. 글은 인상에 명백히 반대한다. 공통 명제 "전기요금을 인상해야 한다."도 적용되지 않았다.
- **주장 추출 0건:** 첫 문장(산업부 발표 수치)과 넷째 문장(시민단체 관계자 인용)이 사실 주장으로 뽑히지 않았다. 신뢰 칸이 "해당 없음"이 된다.

## 발견한 문제

1. **본문 입장 판정 품질.**
   - 프레시안: 근거 인용 2개가 모두 취재원(유희종 지부장) 발언인데 `attribution: author`다. 발화 주체 구분이 지켜지지 않았다.
   - 직접 입력: 반대 글을 `support`로 판정, 명제가 사실 문장.
   - 동아 날씨 기사: 논쟁이 없는데 명제가 빈 문자열이 아니라 날씨 예보 문장이다.
2. **주장 추출이 불안정.** 링크 기사 4건은 모두 정확히 5건(상한)이고 `claimsMayBeOmitted: true`다. 65문장 기사도 5건이라 출처 명시 점수가 기사 일부만 반영한다. 직접 입력에서는 0건이었다.
3. **데일리안 본문 취득 실패.** 허용 호스트는 통과했지만 본문을 가져오지 못했다. 로컬 수집기는 같은 기사를 가져왔으므로 Worker 요청 헤더(User-Agent) 또는 추출 규칙 차이로 추정한다. 미확인.
4. **편향 강도 점수 없음.** `stance-model.json`이 null이다(학습 표본 찬성 17·반대 7, 찬성 재현율 16.7%).
5. **다른 관점 기사 추천이 사실상 비어 있음.** 색인 3,000건이 모두 이용 미승인이라 추천에서 제외된다(11-12 기록). 오늘 다시 실행하지 않았다.
6. **모델이 바뀔 때마다 품질 기준이 없음.** Groq gpt-oss → NVIDIA DeepSeek → Nemotron으로 바뀌었지만 같은 기사 묶음으로 결과를 비교하는 고정 점검이 없다.
7. **문장 수.** 한겨레 2,722자가 65문장으로 나뉘었다(문장당 약 42자). 인용문·소제목이 잘게 나뉘는지 확인이 필요하다. 분모가 커지면 자극 점수가 낮아진다.

## 해결 방안

1. 본문 입장:
   - 6개 정책 주제는 주제 키워드 규칙으로 먼저 찾고 공통 명제를 서버가 고정해 넣는다. 모델이 명제를 새로 쓰지 못하게 한다.
   - 근거 인용 문장에 직접·간접 인용 표지("…고 말했다", 따옴표)가 있으면 서버가 `reported_sources`로 강제한다. 근거가 전부 인용이면 작성자 입장은 `not_expressed`다.
   - 명제 형식 검사: "~해야 한다" 형태가 아니면 명제 없음으로 처리한다.
   - 문장 단위 입장 집계(찬성 쪽·반대 쪽 문장 수, 기자·취재원 구분)로 바꾸면 위 세 오류가 구조적으로 줄어든다.
2. 주장 추출: 상한 5건을 본문 길이에 비례해 늘리거나(출력은 문장 ID만), 사실·의견·출처 표시를 문장별 태그로 받아 서버가 센다. 출처 명시는 이미 있는 규칙(`lib/cited-sources.ts`)을 전체 문장에 적용해 기본 숫자로 쓴다.
3. 데일리안 취득: Worker 요청의 User-Agent와 추출 규칙을 로컬 수집기와 비교한다. 실패 시 화면에 "본문 직접 입력"으로 유도한다.
4. 편향 강도: 문장 단위 라벨 → 주제별 문장 SVM → 기사 좌표 → 같은 주제 분포의 중간값 거리(이전 제안). SVM 통과 전에는 모델의 문장 라벨 집계를 "AI 집계(검증 전)"로 표시할지 사용자 결정.
5. 추천: 이용 검토를 기록하거나, 링크·제목만 보여 주는 추천의 허용 범위를 사용자가 결정한다. 그 전에는 매체 공개 피드(`publisher_feeds`)에서 실시간으로 찾은 기사만 추천한다.
6. 고정 점검 묶음: 실제 기사 링크 10건 + 정답을 아는 가상 글 10건을 정해 두고, 모델·지시문을 바꿀 때마다 같은 묶음으로 성공률·시간·입장·자극·주장 수를 기록한다. 위 직접 입력 글을 첫 가상 사례로 쓴다.
7. 문장 분리: 한겨레 기사로 문장 경계를 확인하고, 소제목·짧은 인용 조각을 앞뒤 문장에 붙이는 규칙을 검토한다.
