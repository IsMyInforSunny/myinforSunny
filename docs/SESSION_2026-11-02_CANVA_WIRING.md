# Canva 메인 UI와 기존 기능 통합 — 작업 기록

작업 시작: 2026-11-01 23:55 KST. 사용자 요청은 약 10분 동안 완성도 우선 작업 후 남은 일은 다음날 진행하는 것이다. 공개 배포 없이 현재 로컬 폴더에서 작업했다.

## 체크리스트 확인

1. Sites·Playwright 스킬과 로컬 미리보기 지침을 읽고 적용했다. 이전 Canva 원본 확인 기록과 사용자 시안의 하늘색 전체 배경·태양/inforcast·기사·3축·반원 게이지·근거·추천 배치를 기준으로 했다. 픽셀 단위 원본 일치 완료로 주장하지 않는다.
2. 모듈 책임을 나누어 병렬 진행했다. 통합 담당자는 Workbench/메인 CSS/검증 기록, Claude Code는 canva-dashboard.tsx 단일 파일, 별도 좌표 감사 에이전트는 좌표 경계 테스트/감사 문서만 담당했다.
3. 실제 Claude Code CLI를 acceptEdits로 실행했다. Claude는 researchStage 전달/완료 하드코딩 제거, stale 경고와 접근성 문구를 수정했다. Claude 자체 검증은 실행하지 못했고 통합 담당자가 실제 전체 검사했다.
4. 기사 입력을 CanvaDashboard의 article 슬롯으로 연결하고 구 workspace/report-panel 바깥 틀을 제거했다. 하늘색 화면 전체가 메인이며 추천은 아래 가로 영역이다. 기존 원문/근거/좌표 모듈은 API·상태를 유지한다.
5. 매체 좌표는 같은 명제에 대한 반대(-1)/맥락(0)/찬성(+1)을 매체별로 모아 기준선을 만들고 입력 입장과 거리를 비교한다. 최소 기사3·매체2·동일가중·범위0~2를 보존했다. 입력 입장 자동 분류와 실제 기사 수집은 아직 미완료다. 메인 편향 항목은 주제 수 대신 매체 좌표 비교로 안내한다.
6. 테스트 기록을 자동 파일 저장하도록 npm run check:record를 추가했다. 기존 제품 동작 기록은 현재 창 메모리에만 존재하며 원문/키를 저장하지 않는 기존 정책을 유지한다.

## 수정과 검증

- 새 UI에 가상 예시→기사 밑줄→설명 표시→신뢰 1/1 갱신 연결을 확인했다.
- 근거 버튼은 기존 #analysis-details를 펼친다. 기사 비교 버튼은 #related-review를 표시한다. 원문 인용·수동 자료 대조·내보내기·팝업 코드 경로를 보존했다.
- 브라우저에서 가상 좌표6개 체험, 입력입장+1을 선택해 거리 **1.000**을 확인했다.
- 내보내기 영역의 JSON 저장 버튼 표시를 확인했다. 이번 브라우저 검증에서 파일 다운로드 자체는 하지 않았다.
- 입력 변경 시 메인에 이전 입력 결과 경고가 보인다. 실제 조사 단계와 현재 분석ID 필터를 유지한다.
- 좌표 경계 테스트에서 원문 길이를 넘는 인용 끝점이 통과하던 오류를 발견해 relationExists에 길이 검사를 추가했다. SVG 접근성 제목도 단일 문자열로 고쳤다.
- Windows에서 로그 파일 잠금이 개발 서버 파일 감시를 종료시키는 현상을 재현했다. 검증 로그/스크린샷/Playwright 상태 폴더를 감시에서 제외하고 재시작했다. 후속 로그 저장과 HTTP 검사 성공.
- 최종 타입 검사·테스트·빌드 모두 종료 코드0. **272 통과·13 건너뜀**. 실제 API opt-in 13개는 실행하지 않았다.
- 최종 로그: docs/test-runs/2026-11-01T15-02-11-282Z/results.json, typecheck.log, test.log, build.log, browser-wiring.log, local-http.log.
- /, /analyze, /popup, /methodology HTTP200. live/webSearch/webFetch false, 실시간 요청503, 로컬 설정 파일 요청403 확인.
- 375px 모바일에서 수평 넘침 없음(document width360 <= viewport375). 화면 이미지 직접 확인. 스크린샷: output/playwright/canva-main-desktop.png, canva-main-mobile.png.
