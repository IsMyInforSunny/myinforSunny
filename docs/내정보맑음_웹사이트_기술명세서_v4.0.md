# 내 정보 맑음? — 웹사이트 기술명세 v4.0

2026-10-30 · **현재 개발 기준**. 개발계획 v4.0·아키텍처 v4.0과 함께 적용합니다. v1~v3는 과거 설계입니다. 이번 개정의 목표는 무료 LLM 기반 M0+M1이며, 자체 모델 학습·브라우저 대형 모델 실행은 필수 조건이 아닙니다. 구현 상태는 §13과 별도 상태 문서에 기록합니다.

## 1. 목적·범위·운영 원칙

공개·가상 본문과 댓글을 입력하면 **논점 분포 / 자극성 / 근거 충분성**을 한 성분표로 제공합니다. AI는 글을 분석하고 사람은 판단합니다. 게시 차단·검열·정치 성향·개인/집단 성격 분류·사회 전체 여론 판정을 하지 않습니다.
필수 M0는 최소 4종 예시 UI(현재 6종 유지), M1은 무료 LLM 실분석·원문 인용 검증·입력 자료 대조입니다. M2 임베딩/PCA와 M3 한 과제 SVM 파일럿은 선택입니다. 확장·페이지 자동 감지·링크만으로 본문 자동 취득·자동 웹검색·학습 모델 배포·추천 피드는 범위 밖입니다.
자료와 문서에서 ‘공격성’은 자극성의 기준에 포함하고, ‘출처 신뢰도 점수’는 쓰지 않습니다. 출처의 권위나 수만으로 근거 충분성을 정하지 않습니다. 실제 대회 규정 원문 확인은 제출 전 게이트로 남깁니다.

## 2. /analyze의 통합 3축 성분표

성분표는 같은 분석 ID·입력 버전의 세 카드를 한 묶음으로 표시합니다. 모바일에서는 같은 순서의 세로 배치입니다. 각 카드에 **축 이름·상태·건수·분모·근거 문장 버튼·유보/미대조·설명**을 넣습니다. 논점 막대·등급·PCA·주장 목록이 각자 독립 점수처럼 흩어지지 않게 합니다.

| 축 | 기본 표시 | 상태 규칙 | 클릭 동작 |
|---|---|---|---|
| 논점 분포 | 논점별 언급 댓글 수 / 전체 댓글 수, 논점 목록 | 확인 논점 2개 이상=복수 논점 확인, 1개=단일 논점 확인, 유효 근거 없거나 분류 불가=판단 유보. 중립성 등급이 아님 | 해당 논점의 실제 원문 구간 |
| 자극성 | 검토 표현 문장 수 / 전체 문장 수, 판단 유보 수 | flagged 1개 이상=검토 표현 있음, 모든 문장 clear=명확한 표현 근거 없음, flagged 0개이고 미처리/유보 존재=판단 유보 | 기준·문맥·원문 전체 문장 |
| 근거 충분성 | 추출 사실 주장 수, 대조 완료 수, 관계별 건수 | 관계 결과와 미대조를 병기. 자료 없음=미대조, 불충분/충돌 존재=추가 자료 필요, 대조 결과가 모두 뒷받침이어도 ‘입력 자료 범위에서 확인’으로 한정 | 주장과 자료 인용을 나란히 표시 |

숫자 1~5 같은 객관적 등급을 임의로 만들지 않습니다. ‘상태’는 위의 관찰 규칙이며 좋은/나쁜 사람·출처 등급이 아닙니다. 본문만 입력하면 논점 목록과 근거만 표시하고 댓글 분포 비율은 해당 없음으로 둡니다. PCA는 선택 ‘분포 탐색’ 보조 탭이며 세 축 점수를 대신하지 않습니다.
결과 상단에는 demo/live·모델 ID·버전·분석 시각·해석 한계를 표시합니다. 입력 변경 후 이전 결과는 분명히 구분합니다. 실패를 고정 예시로 대체하지 않습니다.

## 3. 수치와 확률

- 논점 언급률 = topic이 배정된 고유 댓글 수 / 전체 댓글 수. 다중 배정 합계는 100%를 넘을 수 있습니다.
- 자극성 집계 = flagged 고유 문장 수 / 전체 문장 수. 유보·누락을 별도 표시합니다.
- 자료 뒷받침률 = supported 주장 수 / 정상 대조 완료 사실 주장 수. 대조 진행률 = 정상 대조 완료 수 / 추출된 사실 주장 수. 두 값과 미대조 건수를 함께 표시합니다.
- 분모 0은 null 또는 ‘해당 없음’입니다. 표현 기준이 여러 개여도 문장 수는 한 번만 셉니다.

이 비율들은 건수의 집계라 확률 보정 전에도 계산 가능합니다. 초기 UI는 3/12문장·2/5주장처럼 건수를 우선 표시하고 비율은 보조 표시합니다. ‘자극성 90%’, ‘편향 34/66’처럼 객관적 성향·확률로 읽힐 값은 표시하지 않습니다. 기존 컨셉 이미지는 예시라고 표시하거나 교체합니다.
SVM margin·LLM 자신감은 이 집계와 다른 값입니다. 보정·독립 시험 전 모델 확률을 반환하지 않으며, 보정 후에도 과제별로 정의된 확률만 표시할 수 있습니다. 보정했다고 집계 비율이 진실 확률로 바뀌지 않습니다.

## 4. 분석·인용·자료 대조

LLM은 논점 후보(최대 5), 댓글별 다중 논점, 문장별 표현(clear/flagged/undetermined), 사실/의견/미분류 주장 후보(총 최대 5), 근거 인용, 빠진 논점 검토 질문(최대 2)을 JSON으로 제안합니다. 특정 명제의 찬반 분석은 선택이며 감정 극성과 혼동하지 않습니다.
서버가 원문과 문장 ID를 생성합니다. Span={sourceId,sentenceId,start,end,quote}의 start/end는 UTF-16이며 `sources[sourceId].text.slice(start,end) === quote`를 만족해야 합니다. LLM의 offset은 신뢰하지 않고 문장 안에서 인용을 찾아 다시 계산합니다. 반복 인용은 문장 ID로 구분합니다. 위조 인용은 제외·유보하고 오류를 남깁니다.
이 검사가 보장하는 것은 **인용이 원문에 실제로 존재함**까지입니다. 문맥·해석·논점·자료 관계가 맞다는 뜻은 아니며 별도 사람 평가를 합니다. JSON strict 출력도 의미적 정확성을 보장하지 않습니다.
자료 대조는 기본 분석 후 별도 버튼으로 호출합니다. 사용자가 최대 1개의 사실 주장을 선택·수정하고 참고자료 본문 최대 2개를 붙여 넣습니다. 같은 본문 안의 시점·대상·수치·부정·인용 맥락을 비교하며 전체 인터넷의 진실을 판정하지 않습니다. 자동 URL 취득은 미연결이고, 입력 URL은 출처 메타데이터일 뿐입니다.

| 내부 outcome | 화면 표시 |
|---|---|
| supported | 출처에서 확인됨 · 입력 자료 기준 |
| contradicted | 입력한 출처와 다름 |
| conflicting | 입력 자료 간 내용이 다름 |
| insufficient | 추가 근거 필요 |
| unchecked | 아직 대조하지 않음 |
| inaccessible | 자료 본문 확인 불가 |
| not_applicable | 사실 확인 대상 아님 |

‘출처에서 확인됨’은 주장을 뒷받침하는 구절을 입력 자료에서 찾았다는 뜻입니다. 원 사이트를 실제 취득하지 않았다면 ‘입력 자료·원 사이트 미확인’을 함께 표시합니다. 자료 없음은 거짓이 아니고, LLM 기억으로 출처·링크·날짜를 만들어 채우지 않습니다.
뒷받침과 반대 내용이 함께 있으면 conflicting, 시점이 다르면 불일치 한계·insufficient, 의견이면 not_applicable로 처리합니다. 질문·논점 보완은 추천 피드나 무조건 반대 관점 제공이 아닙니다.

## 5. 무료 LLM 어댑터와 선택

서버 측 `LLMProvider`는 analyze/verify와 무관하게 `generateStructured(schema,instructions,input,signal)`와 안전한 사용량·요청 제한 메타데이터만 반환합니다. Groq의 OpenAI 호환 `/openai/v1/chat/completions`와 `response_format.json_schema`를 첫 구현으로 삼고, Zod로 다시 검증합니다. 응답 원문·키·사용자 입력을 로그로 출력하지 않습니다. strict 요구에 맞춰 모든 필드 required·additionalProperties:false로 설계합니다.
조건부 후보: `openai/gpt-oss-120b`, `qwen/qwen3.8-27b`. 둘을 같은 한국어 10사례에서 비교해 JSON·인용·해석·토큰·지연 결과를 남긴 뒤 기본 모델 1개를 동결합니다. 실제 비교 전 한국어 우열을 단정하지 않습니다. 내장 브라우저 검색·도구 호출은 사용하지 않습니다.
Groq Free 공식 기준은 후보별 30 RPM·1K RPD·8K TPM·200K TPD입니다(2026-10-30 확인). 계정 정확한 한도·공급자 응답 헤더를 우선합니다. ‘약 50건’은 가정에 따른 추정일 뿐이므로 명세상 보장 횟수로 쓰지 않습니다.
Gemini는 청소년 대상 API 클라이언트 제한 때문에 제외, GitHub Models는 종료되어 제외합니다. OpenRouter·Cerebras·FriendliAI는 미검증 예비 조사 대상이며 순차 fallback을 활성화하지 않습니다. 무료 모델 이름이 사라지면 오류를 반환하고 운영자가 검토한 뒤 바꿉니다. 유료 모델·기존 OpenAI 키·Cloudflare Workers AI로 자동 전환하지 않습니다.

## 6. MVP 입력·API 계약

v4 적용 상한은 본문 2,000 UTF-16 코드 단위, 댓글 5개×200, 선택 명제 160, 선택 주장 1개, 참고자료 2개×1,500입니다. 코드·화면의 상한을 이 값으로 변경했습니다. API 계약 2.1의 실제 입력은 transmissionConsent=true를 요구하며 예시 경로는 별도입니다. 한도는 품질·토큰 실측 후 문서/코드/화면을 함께 바꿉니다. 조용한 절단은 금지합니다.

- `GET /api/capabilities`: live, selectedProvider/model(비밀 아님), limits, features, reason, schema/rubricVersion. 키·토큰·계정 식별자 반환 금지.
- `POST /api/analyze`: kind=demo는 fixtureId, kind=text는 body/comments/proposition. 기본 결과는 sources/topics/topicAssignments/expressions/claims/perspectiveQuestions/indicators/warnings/versions/inputVersion과 mode/status.
- `POST /api/verify`: 선택 주장·origin·원문 문맥·참고자료 본문·선택 URL 메타데이터. 결과는 claimId/outcome/execution/relations/temporalFit/limitations/provenance.
- 결과 상태: demo/live, success/partial; 요청 실패는 typed error. FEATURE_UNAVAILABLE, INPUT_TOO_LARGE, RATE_LIMITED, FREE_QUOTA_EXHAUSTED, PROVIDER_UNAVAILABLE, INVALID_MODEL_OUTPUT, TIMEOUT, PRIVACY_INPUT_REJECTED를 구분합니다.

형식·원문·지표 계약은 서버가 소유하고 기존 UTF-16·분모 검증 함수를 재사용합니다. 이전 UI 계약과의 호환 변경은 명시적 schema migration으로 관리합니다. 새 문서가 있다고 기존 코드가 이미 새 한도를 적용한 것으로 간주하지 않습니다.

## 7. 호출·토큰 제한과 실패 처리

사용자별 3회/분·20회/시간은 남용 완화 상한이며 공급자 무료 한도를 보장하는 수치가 아닙니다. 분석과 자료 대조는 각각 1회 호출로 셉니다. 공급자 단위 공유 예산·동시성·입출력 토큰 예약을 별도로 적용합니다.
초기 전역 상한: 동시 외부 호출 1개, 60초 이동창 예약 토큰 7,000 이하, UTC 일일 사용+예약 120,000 토큰 이하, 일일 요청 500회 이하. 입력·시스템·스키마 토큰과 최대 출력 2,000을 합쳐 예약하고 1건 6,500 초과 예상이면 입력 축소를 요청합니다. 이는 앱의 보수적 설정이며 공급자 정책 수치가 아닙니다. 추론 토큰도 완료 토큰 한도·실제 usage에 포함해 정산합니다.
우선 공식 tokenizer/공급자 사용량을 검증하고, 정확한 사전 토큰화가 없으면 UTF-8 바이트 기반 보수적 상한으로 거절할 수 있습니다. 보수적 추정으로 허용 입력이 너무 작아지면 스키마를 줄이고 기능을 단계별 호출로 나눕니다. 과소 추정한 채 긴 요청을 보내지 않습니다.
공급자 예약량·실제량·예상 밖 오류·계정의 다른 앱 사용을 고려합니다. 429와 reset/retry-after를 반영해 당분간 요청을 막습니다. 스키마 보완·공급자 변경·429 자동 재시도는 초기 MVP에서 하지 않습니다. 재실행은 사용자 선택이며 새 예산을 사용합니다. 네트워크 실패도 실제 청구/소비 여부가 불명확하면 예약을 보수적으로 유지합니다.
공급자 25초·전체 요청 40초 마감, 취소 신호 전달을 기본으로 합니다. 브라우저 취소가 이미 소비한 공급자 토큰을 환불한다고 보장하지 않습니다. 중복 requestId는 다시 외부 호출하지 않습니다. 실패 시 예시를 자동 성공 응답으로 내보내지 않습니다.
단일 프로세스 시연용은 메모리 세마포어·카운터로 충분하지만 재시작 시 소실·다중 인스턴스 비공유임을 표시합니다. 공개 Sites/분산 운영은 D1 같은 원자적 공유 저장소를 사용하며 사용자 글 없이 최소 요청·사용량 계수만 보관합니다. 이동창 토큰 예약은 기존 D1 코드에 추가 구현이 필요합니다.

## 8. 개인정보·청소년·데이터

화면에 ‘가상 또는 사용 가능한 공개 자료만 입력하세요. 이름·연락처·비공개 대화는 넣지 마세요. 실시간 분석 시 입력이 Groq로 전달됩니다’를 표시하고 전송 전 확인을 받습니다. 전화번호·이메일 등 탐지 가능한 개인정보는 수정하도록 차단합니다. 탐지기가 모든 개인정보를 제거한다는 보장은 하지 않습니다.
정치 성향이나 사람·집단의 특성을 추정하지 않습니다. 집단 일반화라는 표현 기준을 식별하는 것과 작성자/집단 자체를 분류하는 것은 구별합니다. 서비스 입력·결과를 자동 학습하거나 DB에 저장하지 않습니다. 사용자가 선택한 검토 기록만 로컬 내보내기로 저장합니다. 피드백은 운영자 검토 후 지침·버전 갱신이며 자동 재학습이 아닙니다.
Groq 운영자는 18세 이상 계정 요건과 청소년 앱 조건을 확인해야 합니다. API 데이터의 기본 미보관과 예외 보관은 구별합니다. 공식 문서상 신뢰성·남용 조사 시 최대 30일 임시 보관 예외가 있고 ZDR 설정을 제공합니다. 활성화 전에 계정의 Data Controls를 확인하며 무조건 ‘학습·보관 전혀 없음’이라고 안내하지 않습니다. 사용량 메타데이터는 별도로 남을 수 있습니다.
대회 규정·동의·제출 자료 사용 조건은 확인 항목으로 관리합니다. 제공된 양식과 PPT만으로 최신 대회 규정 전체를 확인했다고 주장하지 않습니다.

## 9. 선택 임베딩·PCA·SVM

M2는 API 비용 없는 공개 다국어 encoder 후보를 고정 revision·tokenizer·pooling·license와 함께 오프라인 실행해 한국어 댓글 벡터를 만듭니다. bge-m3 등은 후보일 뿐 최종 채택하지 않았고 모델 크기·품질을 시험합니다. PCA는 데이터 분포 탐색이며 최대 분산 축에 정치·도덕·찬반 이름을 붙이지 않습니다.
M3는 표현 등 **한 과제**에만 한정합니다. 사람 2명 독립 라벨·조정·그룹별 train/calibration/dev/test, 규칙·LLM 단독·임베딩+SVM의 같은 동결 시험 비교, macro-F1·클래스별 precision/recall·coverage·지연을 표로 보고합니다. SVM 자체는 학습이 필요하며 무료 LLM을 쓴다고 사라지는 절차가 아닙니다. 조건 미충족이면 미실시로 남깁니다. 보정 자료가 부족하면 확률을 제공하지 않습니다.
기존 engine.py·project.py·model-head.ts는 연구 자산으로 보관하지만 실시간 결과에 몰래 혼합하지 않습니다. LLM 설명을 SVM의 실제 판단 이유로 붙이지 않습니다.

## 10. 평가와 최소 수용 기준

선별 시험 10사례의 JSON 유효율 ≥90%, 채택 인용 원문 일치 100%. 본 평가 사람 검토 문장 ≥60·원문/스레드 ≥15그룹, 표현 macro-F1 ≥0.75·flagged precision ≥0.80·처리율 ≥0.80을 목표로 고정합니다. 유보 포함·제외 결과를 모두 공개하고 평가셋 구성·라벨 분포를 함께 제시합니다.
자료 관계 ≥20쌍의 해석 적절성 ≥80%, 조정 전 사람 2명의 일치율·Cohen kappa·분모 보고, kappa <0.60이면 지침 재검토. 성공 지연 p95 ≤30초 목표와 timeout·실패율을 함께 보고합니다. 모든 값은 **사전 목표**이며 실제 달성 수치는 아직 없습니다. 전체 서비스의 단일 정확도로 합치지 않습니다.
위조 인용·허위 취득·잘못된 집계·비밀키 노출은 0건이어야 합니다. 누락은 clear가 아니라 undetermined로 채우고, 기권으로 성능을 부풀리지 않습니다. 평가 지침·모델·프롬프트·출력 제한을 동결한 뒤 시험합니다. 실패하면 설명·범위를 바꾸고 재시험을 별도 기록합니다.

## 11. 호스팅·자원 검증

서버는 키 보관·검증·요청/토큰 제한·25/40초 마감을 소유합니다. 브라우저·GitHub Pages만으로 이 경로를 운영하지 않습니다. 기존 Sites의 Worker 실행 환경을 우선 사용하고 키는 서버 secret으로만 넣습니다. 무료 AI 서비스와 사이트 호스팅의 요금은 별개이며 현재 계정의 호스팅 비용 조건은 따로 확인합니다. 개발자 PC 상시 실행은 요구하지 않습니다.
Cloudflare Workers 공식 문서에서 HTTP wall time과 CPU time은 별도이며 연결 유지 시 HTTP의 고정 duration 제한은 없다고 안내합니다. 그러나 이것을 Sites의 프록시/플랜도 무제한이라고 해석하지 않습니다. Sites의 실제 플랫폼 경로에서 25/40초 마감·client disconnect·CPU·128MB 메모리 환경·동시성·공유 제한 저장소를 실측하고 결과를 기록한 뒤 활성화합니다. 60초 처리를 보장하지 않습니다.
시연 서버 메모리 제한기는 단일 프로세스에서만 사용합니다. 분산 배포에서는 공유 제한기를 활성화해야 합니다. 호스팅 시간이 부족하면 출력·입력을 줄이거나 단계를 분리하고 timeout을 명확히 표시하며 무단 유료 업그레이드를 하지 않습니다.

## 추가 운영 방침: 지금은 무료, 유료는 나중에 명시적으로 전환

현재는 Groq Free만 구현·검증하며 `FREE_ONLY=true`, `ENABLE_PAID_PROVIDER=false`, `PAID_ACTIVATION_CONFIRMED=false`를 기본으로 둡니다. Groq 키·운영 조건이 준비되지 않아 실시간 활성화는 아직 안 됐습니다. 기존 OpenAI 키를 생성·이동·업로드·호출하지 않습니다. 무료 한도 초과 시 유료 fallback은 없습니다.
향후 사용자가 전환을 명시하면 기존 OpenAI 키의 승인된 저장 위치를 재사용할 수 있지만, 키가 존재한다는 사실만으로 호출하지 않습니다. 무료 전용 해제 + 별도 유료 활성화 + 명시적 전환 확인을 서버에서 모두 검사하며, 그때 OpenAI 어댑터 구현/등록·모델 선정·비용 예산·전송 안내·같은 한국어/JSON/인용 시험을 함께 완료합니다. 현재는 해당 어댑터가 등록되지 않아 유료 플래그만 바꿔도 호출할 수 없습니다.
공통 분석 결과·인용 검증·집계 계약은 유지하고, 제공자 고유 요청 형식·시간 제한·사용량 처리는 서버 어댑터에 둡니다. AI 제공자 전환과 호스팅 전환은 별개입니다.
