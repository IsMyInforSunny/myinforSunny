## 수정 1 — 주제 규칙의 빈틈 (사례 A)

`lib/stance-model.ts`의 `stanceTopicRelevant`가 사례 A를 전기요금 주제로 잡지 못한다. `electricity_prices` 규칙은 "전기요금" 뒤 35자 안에 `인상|인하|동결|원가|한전|한국전력`이 있어야 하는데 본문은 "올리기로"다. 그래서 공통 명제가 적용되지 않고 모델이 쓴 명제가 그대로 통과했다.

- 6개 주제 규칙에 일상 표현을 추가한다: `올리|내리|오르|인상안|조정|현실화|동결` 등 주제별 동의 표현.
- 추가할 때마다 3,000건 보존 자료로 주제 판정 건수 변화를 보고한다. 관련 없는 기사(예: 주택 화재)가 새로 잡히지 않는지 표본을 확인한다.
- 사례 A와 "전기료가 오른다", "최저시급을 올려야" 같은 변형을 단위 테스트에 넣는다.

## 수정 2 — 공통 명제가 없을 때 명제 형식 검사 (사례 A, C)

`lib/server/analyze.ts`의 `assembleAnalysis`는 기대 명제가 없으면 모델이 쓴 명제를 형식 검사 없이 받는다.

- 사용자 명제도 공통 명제도 없을 때, 모델 명제가 당위·찬반 가능한 형태(`…해야 한다`, `…하지 말아야 한다`, `…이 바람직하다` 등)가 아니면 명제를 빈 문자열로 바꾸고 label을 `not_expressed`로 둔다. 근거 인용은 버린다.
- 사실 서술·예보·사건 요약 문장(`…했다`, `…예상된다`, `…이다`로 끝나는 서술)은 명제로 인정하지 않는다.
- 이 경우 `BODY_POSITION_UNAVAILABLE` 경고 대신 "찬반으로 비교할 논점이 없는 기사"라는 정상 상태로 표시한다.

## 수정 3 — 발화 주체를 서버가 확인 (사례 B)

지금은 모델이 준 `attribution` 값만 믿는다. 서버가 근거 문장을 직접 확인한다.

- 근거 인용이 놓인 문장마다 인용 표지를 규칙으로 검사한다.
  - 따옴표(" " “ ” ‘ ’) 안에 인용 구간이 들어 있음
  - 전달 동사: `말했다|밝혔다|강조했다|주장했다|지적했다|설명했다|전했다|요구했다|촉구했다|우려를 표시했다|예측했다|…라고|…다고|…다며`
  - 출처 표지: `…에 따르면|…은 …에서`
- 판정:
  - 근거 문장이 **모두** 인용 표지에 해당하면 `attribution`을 `reported_sources`로 강제한다. 방향 label은 기존 규칙대로 `not_expressed`가 된다.
  - 일부만 해당하면 인용 표지가 없는 근거만 남겨 다시 판단한다. 남는 근거가 없으면 `reported_sources`다.
  - 모델이 `reported_sources`라고 했는데 인용 표지가 하나도 없으면 `unclear`로 낮춘다.
- 규칙이 값을 바꾼 경우 응답에 표시를 남겨(예: `attributionSource: 'server_rule'`) 화면과 내보내기에서 구분한다.
- 이 규칙은 `lib/cited-sources.ts`의 기존 인용·출처 탐지와 겹친다. 새로 만들지 말고 그 모듈의 문장 단위 탐지를 재사용한다.

## 수정 4 — 방향 검증용 고정 점검 묶음

모델이나 지시문이 바뀔 때마다 같은 입력으로 결과를 비교한다.

- `research/` 또는 `scripts/`에 점검 스크립트를 만든다. 입력은 실제 링크 10건(매체 4곳 이상, 6개 주제 + 비정책 기사 포함)과 가상 글 10건이다.
- 가상 글 10건은 정답을 정해 둔다: 주제별 찬성 글·반대 글, 취재원 인용만 있는 보도, 논쟁 없는 글. 사례 A가 첫 사례다.
- 기록 항목: HTTP 상태, 소요 시간, 명제, label, attribution, 자극 검출 수/문장 수, 사실 주장 수, 경고 코드.
- 가상 글은 기대값과 일치 여부를 표로 낸다. 이 일치율은 "고정 가상 사례 일치"이며 정확도로 표기하지 않는다.
- 실제 모델을 호출하므로 opt-in으로 실행하고, 결과 요약만 `docs/test-runs/`에 저장한다(원문 제외).
