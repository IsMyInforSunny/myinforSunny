# 내 정보 맑음 — 기술명세 v5.0

작성일: 2026-10-31. 개발 기준 문서. v4.1은 이전 구현 기록으로 보관한다. 이 문서의 ‘구현’은 코드 상태이며 공개 배포·실제 검색 공급자 검증과 구분한다.

## 제품 목표와 상태

기사를 붙여 넣으면 본문 논점 분포, 자극성, 외부 조사를 통한 신뢰성 검토, 다른 관점 및 관련 기사를 제공한다. 신뢰성은 수동 참고자료 입력으로 대체하지 않는다. 기사 전체의 진실 확률이나 언론사 점수를 만들지 않는다.

## 분석과 수치

입력은 본문 2,000자, 댓글 5개×200자, 선택 명제 160자다. 전체 처리 단위는 24개 이하. 긴 문장은 약 500 UTF-16 단위로 분할하며 최대 8개의 끝 문장부호 예외를 둔다. 처리 단위와 자연 문장은 다르다. `sentence-3.1`은 원문 위치를 보존한다. 이전 구간으로 만들어진 결과는 다시 분석해야 한다.

본문의 모든 처리 단위에 `bodyTopicAssignments`를 만들고 자연 문장별로 합친다. 누락·중복·알 수 없는 논점은 판단 유보 처리한다. 본문과 댓글을 분리한다. 한 문장이 여러 논점에 해당하면 비율의 합이 100%를 넘을 수 있다. 분모에는 기타·유보를 포함한다. 표현 검토 건수 역시 긴 문장의 조각을 중복 집계하지 않는다. 분모 10 미만이면 퍼센트를 표시하지 않는다. 편향·공격성·진실 확률은 반환하지 않는다.

신뢰성은 추출된 사실 주장 최대 5개를 대상으로 한다. 조사 완료·미확인·뒷받침·상충·불충분·실제 취득 출처 수를 표시한다. 추출 누락 가능성과 전체 기사 미검증 한계를 알린다. 도메인 수를 독립 근거 수로 해석하지 않는다.

## API와 자동 조사

기존 `/api/analyze`, `/api/verify`, `/api/capabilities`, `/api/health`, `/api/news`를 유지한다. `/api/research`는 다음 세 작업을 받는다.

1. `plan`: 개인정보·인용·처리 단위를 검증하고 주장별 영문 검색어를 계획한다. 원문 해시·호출자·만료 시간을 서버 서명에 묶는다.
2. `discover`: 서명된 계획의 검색어만 실행한다. 고정 검색 엔드포인트를 사용하고 운영자가 허용한 정확한 호스트만 본문을 취득한다. 리다이렉트를 따르지 않는다. 주장당 최대 2개, 각 최대 1,500자 발췌를 만든다. 원문 위치·추출 버전·해시·취득 시각·실패 이유를 남긴 서명 자료를 브라우저 메모리에 반환한다.
3. `compare`: 서명·호출자·입력 해시를 확인한 자료만 `web_fetched`로 대조한다. 모델은 자료 문장 ID를 고르고 서버가 인용과 위치를 복원한다. 동일 문장 반복 시에도 선택한 위치를 유지한다. 제안에 대한 명시적 입장은 사실 수치 상충과 별도로 분류한다.

자동 단계는 별도 공개 자료 검색·전송 동의 후 실행한다. 무료 모델 예산을 지키기 위해 모델 호출 사이 약 61초를 기다릴 수 있다. 취소·실패·자료 없음은 완료로 세지 않는다. 부분 결과는 유지한다. 출처 있는 다른 입장은 실제 취득 본문 인용이 일치할 때만 표시한다. 기사 본문 전체를 화면에 복제하지 않고 제목·링크·짧은 인용만 표시한다.

## 무료 운영·보안

Groq `openai/gpt-oss-120b`를 유지한다. 확인된 계정 한도는 30 RPM, 1,000 RPD, 8,000 TPM, 200,000 TPD. 내부 모델 호출 예약 6,500토큰, 출력 최대 2,000토큰, 전역 동시 호출 1개, 타임아웃 60초, IP별 3회/분·20회/시간이다. 일일 토큰 예산 120,000은 계정 한도의 80%보다 낮다. 유료 제공자·유료 자동 전환은 꺼 둔다.

검색은 별도로 IP별 3회/분·20회/시간, 전역 하루 200회 안전 상한과 공급자 대기 상태를 사용한다. 이 값은 검색 업체의 공인 무료 한도가 아니다. 승인된 서비스의 실제 한도가 더 작으면 낮춰야 한다.

키는 서버 secret에만 둔다. D1에는 원문·검색어·분석 결과 없이 HMAC 호출자와 시각·예산·대기 상태만 저장한다. 조사 계획과 공개 발췌는 만료되는 서명 묶음으로 브라우저 메모리에 둔다. 사용자 작성 자료에 `web_fetched`를 붙일 수 없다. 로그에 원문·키를 출력하지 않는다.

## 검증과 남은 출시 조건

회귀 검사 통과는 정확도 검증이 아니다. 검색 후보 GDELT는 실제 점검에서 429를 반환했으며 아직 안정적인 연결로 간주하지 않는다. 검색 승인 플래그를 켜지 않는다. 단순 HTML 정리 방식의 기사 추출은 본문·보일러플레이트·인코딩·출처별 허용 조건 검증이 남아 있다. 의견만 있는 글의 관련 기사 탐색, 조사 결과 내보내기, 자동 조사 모바일·취소 UI 검증도 남은 과제다.

2026-10-31 검증 기록: 회귀 172개 통과, 실제 무료 Groq 가상 기사 1건 성공(3,869토큰). 본문 논점 2개·사실/의견 주장 2개·본문 문장별 배정과 다른 관점 제안을 확인했다. 이는 독립 정확도 평가나 실제 기사 검색 검증이 아니다.
