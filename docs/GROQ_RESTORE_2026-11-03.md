# 기존 Groq 연결 복구와 실제 화면 검증

기존 키 파일을 다시 발급하거나 복사하지 않고 로컬 사이트의 분석 서버에 연결했다. `.dev.vars`의 선택 설정 `INFORCAST_GROQ_KEY_FILE`은 기존 키 파일의 경로만 보관한다. 상대 경로는 프로젝트 루트를 기준으로 해석한다. 이후 `npm run dev:local`로 같은 연결을 재사용할 수 있다.

`scripts/local-groq-runtime.mjs`는 로컬 `serve`에서만 이 참조를 읽는다. 허용한 설정과 Groq 키는 서버 프로세스 메모리 및 Worker `secret_text` 바인딩에 전달하며 생성하는 로컬 설정 파일에는 키 값을 넣지 않는다. `build`에서는 파일 읽기·환경 변경 전에 반환한다. 실제 키 파일·로컬 설정·통신 기록은 Git에 포함하지 않는다. 공개 배포 서버의 비밀 설정은 이 로컬 연결과 별개다.

사용자가 현재 Free / $0 요금제와 조직 콘솔 한도 RPM30·RPD1000·TPM8000·TPD200000을 제공했고 기존 연결의 재사용을 요청했다. 이용 자격과 청소년 앱 조건은 기존 v4.1 사용자 확인을 유지했다. 프로젝트별 추가 제한 화면은 확인하지 못했으므로 조직 기본 한도를 프로젝트별 확정값으로 설명하지 않는다. 공급자가 더 낮은 한도를 반환하면 기존 429 중지·대기 처리를 따른다. 자동 재시도나 유료 대체는 사용하지 않는다.

사이트 보호는 예약6500토큰·이동60초7000토큰·동시1개·일일120000토큰/500회로 유지한다. 이번 검증의 실제 요청은1회, 소비3871토큰으로 로컬 예산 DB에 기록됐다. 예산 기록에는 입력 원문이 들어가지 않는다.

## 실제 검증

- `/api/capabilities`: HTTP200, `live:true`, 검색·본문 취득은 비활성.
- 브라우저에서 공개용 가상 문장2개를 입력하고 전송 동의 후 실제 `/api/analyze` 요청: HTTP200, `mode:live`, `status:success`.
- 사실 주장1개·의견1개·표현 분석2개. 화면 자극0점(n=2), 편향 산출 대기, 신뢰 산출 대기(n=1). 근거 부족을 점수0으로 확정하지 않았다.
- 응답과 화면에 키 형식 문자열 없음. 빌드 산출물94개에서 기존 키의 실제 값이 발견되지 않았다.
- 개발 서버의 `.dev.vars`, 로컬 런타임 설정, 기존 외부 키 파일에 대한 파일 요청은 모두 HTTP403이며 키 문자열을 반환하지 않았다.
- 예시7종의 세 축 점수·분모와 JSON2.5 일치, 원문 선택 동의, 이전 입력 표시,375/1280px 메인 및 방법론·팝업 모바일 검증 통과. 페이지 예외0개.

이 결과는 로컬 사이트의 실제 Groq 분석 연결을 검증한 것이다. 독립 사람 평가에 따른 분석 정확도, 실제 외부 기사 조사, SVM 편향 모델의 실측 평가, 공개 사이트 배포 완료를 의미하지 않는다. 편향 모델 입력은 여전히 `null`이다.
