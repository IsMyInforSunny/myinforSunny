## 문제점과 고칠 점

### 1. 이전 성능 수치를 다시 확인해야 한다 (가장 중요)
라벨 오류가 학습 라벨에만 있었는지, **고정 평가 라벨에도 있었는지** 보고에 없다. 같은 빠른 모델 라벨로 평가했다면 "원전 내부 성능 기준 통과"(방향 F1 0.81, 찬성 재현율 0.75 등)는 틀린 정답과의 일치도라 믿을 수 없다.
- 정제 라벨로 **평가 세트부터** 다시 채점한다. 학습 전에 기존 모델을 새 평가 라벨로 다시 재서 "라벨 정제 전후" 수치를 나란히 기록한다.
- 기존 원시 라벨과 정제 라벨의 문장 단위 불일치율을 주제·쟁점별로 공개한다. 불일치가 큰 쟁점은 정의부터 다시 본다.

### 2. 정제 라벨도 단일 AI 1회 검토다
"기존 라벨과 모델 예측을 보지 않는 별도 AI 검토"는 좋지만, 여전히 한 모델이 한 번 본 결과다.
- 두 번째 독립 라벨(다른 모델 또는 같은 모델의 다른 지시문)을 최소 평가 세트에 붙이고, **두 라벨이 일치한 문장만** 평가에 쓴다. 불일치율 자체가 "이 쟁점은 AI도 헷갈린다"는 지표다.
- 팀원 2명의 60문장 라벨(이미 결정 대기 항목)은 이 일치한 평가 세트에서 뽑으면 가장 효율적이다.

### 3. 쟁점 정의가 겹친다 (라벨 오류의 원인)
보고된 오류 "주식 평가액 증가 → 소득대체율 인상 찬성"은 쟁점 경계 문제다. `voice-article-issue-rules.json`에서 `replacement`가 `연금 급여|받는 연금`까지, `fund_risk`가 `주식 투자|기금 … 운용`까지 잡아 한 문장이 두 쟁점에 걸린다.
- 쟁점마다 **"찬성으로 세는 것 / 세지 않는 것"** 예시 3~5개씩을 라벨 지시문과 문서에 고정한다. 예: "기금 수익률이 올랐다"는 `fund_risk` 사실 서술(중립)이지 `replacement` 찬성이 아니다.
- 성과·통계 보도는 정책 찬성이 아니라는 규칙을 쟁점별로 다시 명시한다.

### 4. 비교 집합 0개 — 범위 기사를 쓰는 방법을 정해야 한다
현재 좌표 56건(점 15·범위 41)인데 분포는 **점좌표만** 세서 0개다. 범위 기사를 빼면 앞으로도 집합이 거의 안 생긴다(점이 되려면 미확정 0이어야 하는데 기사 대부분에 유보가 남는다).
- **권장: 구간 중앙값.** 각 기사를 [하한, 상한] 구간으로 두고(점은 하한=상한), 하한들의 동일가중 중앙값과 상한들의 동일가중 중앙값으로 기준선을 **구간**으로 낸다. 중간점 대입이 없어서 "범위를 점으로 바꾸지 않는다" 원칙과 맞는다. 입력 점수도 구간 대 구간 거리의 최소·최대로 낸다.
- 적격 매체 수는 점+범위 기사를 함께 센다(매체당 3건·2곳 유지).
- 기준선 구간 폭이 0.5를 넘으면 "기준선 불확실"로 표시하고 방향을 말하지 않는다.
- 이것은 Codex가 답을 기다리는 항목이다. 사용자 결정이 필요하다.

### 5. 분기 단위는 지금 표본에 비해 너무 잘다
좌표 56건을 18쟁점 × 약 12분기에 나누면 칸당 평균 0.3건이다. 분기 → 반기 → 전체 순서는 맞지만 실제로는 거의 모두 "전체 기간"으로 떨어진다.
- 우선 **기사가 많은 3~4개 쟁점**(주택 공급, 의대 정원, 원전 확대, 최저임금 인상)에 임베딩·라벨을 집중해 "전체 기간" 집합부터 적격으로 만든다. 18쟁점 전부를 동시에 키우지 않는다.
- 화면에는 실제로 쓴 범위("2024-01~2026-11 전체")를 반드시 적는다(이미 구현).

### 6. 쟁점 미확정 822건(27%)
제목·도입부·본문 규칙이 동점이거나 근거가 없으면 유보한다. 안전하지만 커버리지를 크게 깎는다.
- 동점일 때 LLM 분석의 `bodyPosition.proposition`(이미 6개 공통 명제로 고정됨)을 결정 근거로 쓴다.
- 그래도 두 쟁점이 비슷하면 "주 쟁점 2개"를 각각 계산해 둘 다 보여 주는 편이 유보보다 낫다.

### 7. 임베딩 병목: 예약 방식과 외부 전송 승인
- 누락 문장 처리에 "1,922회, 최소 107일"로 추정했는데, 호출당 예약 6,500토큰은 **생성형 분석용 보호값**이다. 기존 기록상 임베딩 실제 사용량은 14회 20,579토큰(호출당 약 1,500), 1회 155토큰이었다. 예약이 실제보다 4배 이상 크다.
  - 임베딩은 배치 텍스트를 토크나이저로 세어 그만큼만 예약하는 별도 장부로 나누면 같은 일일 한도로 4배 이상 빠르다. 보호 한도를 바꾸는 일이라 사용자 승인이 필요하다.
- 실제 기사 문장을 NVIDIA로 보내는 호출이 자동 승인에서 거부됐다. 이것은 **사용자가 명시적으로 허락하면 풀리는 문제**다. 허락 범위를 "보관 기사 3,000건의 분석 범위 문장을 NVIDIA 임베딩 API로 전송"처럼 구체적으로 적어 Codex에 주면 된다.
- 대안: 오픈 임베딩 모델(예: bge-m3, multilingual-e5)을 내 컴퓨터에서 돌리면 외부 전송·예산이 없다. 다만 운영 사이트에서도 같은 모델로 입력 기사를 임베딩해야 해서, 사이트 쪽 실행 방법을 먼저 확인해야 한다. 재학습이 어차피 남아 있으므로 지금이 바꿀 시점이긴 하다.

### 8. Python–TypeScript 일치 검사를 실제로 돌려야 한다
Codex 기록은 `stance-runtime-parity.test.ts`가 "Windows `py` 부재, scikit-learn 미설치"로 완료되지 않았다고 한다. 이 컴퓨터에는 `py`(Python 3.14.3)와 scikit-learn 1.9.0이 있다. Codex 실행 환경에서만 안 보이는 것으로 보인다.
- `PYTHON_EXECUTABLE`을 `py`의 실제 경로로 지정해 이 검사를 반드시 통과시킨다. 학습(Python)과 사이트 추론(TypeScript)의 결과가 같다는 유일한 증거다.
